# Game Core 규칙 범위

`@kbo/game-core`의 compiler는 `StagingGameDocumentV2` 평면 원장을 입력받아 DB 적재용 원자적
play·movement·PA·상태·기록과 finding을 결정적으로 만든다. Naver 누적 상태는 관측값으로만
비교하고 계산 상태를 덮어쓰지 않는다.

규칙 판단은 [KBO 경기 운영 규정](https://www.koreabaseball.com/Kbo/League/GameManage.aspx)과
[MLB Official Baseball Rules](https://www.mlb.com/official-information/official-rules)을 근거로 한다.

## 입력 사실과 파생 사실

원장에는 결과 판정, 선수, 투구, 실제 기존 주자 이동, 교체와 중계 문구 같은 원천 사실을 둔다.
balls, strikes, outs, bases, score, PA lifecycle, 타자·투수 기록과 DB play는 compiler가 계산한다.

타석 결과에 연결된 주자 행은 `plateResultEventId`로 묶는다. 사이에는 판독·공지 같은 비상태 행만
올 수 있다. compiler는 다음을 하나의 임시 상태에서 검증하고 성공할 때 한 번만 commit한다.

- 결과에서 유일하게 결정되는 타자주자 기본 movement
- 기본과 다른 타자 생존 `batterDestination`
- 결과 행이 직접 기록한 추가 아웃
- 원장에 실제 존재하는 기존 주자의 연결 `runner_advance`

기존 주자의 강제 진루나 홈런 득점을 결과명만으로 만들지 않는다. 연결된 주자 행이 없으면 누락
finding으로 남긴다. 같은 주자의 다단계 경로는 직전 임시 위치에서 이어져야 하고, 아웃·득점 후
다시 이동할 수 없다. 최종 중복 점유나 존재하지 않는 주자의 이동은 play 전체를 차단하며 원래
상태를 부분 변경하지 않는다.
같은 베이스로의 안전 도착 행은 해당 베이스를 떠난 것으로 세지 않는다. 그 뒤의 실제 진루·득점은
연속 경로로 검증하며 원문 행을 모두 유지한다. 같은 출발지를 실제로 두 번 떠나는 이동은 계속 차단한다.

같은 반이닝에서 투구와 투구 사이에 연속해서 기록된 독립 `runner_advance` 행은 사유가 달라도
하나의 live-ball play로 묶는다. 폭투 진루 뒤 같은 live ball에서 태그 아웃되거나, 한 주자는
폭투로 진루하고 다른 주자는 득점하는 식으로 Naver가 한 플레이를 여러 사유로 나눠 적을 수 있기
때문이다. compiler는 모든 출발 베이스를 임시 상태로 옮긴 뒤 같은 주자의 추가 이동은 임시 위치에서
이어가고, 최종 위치를 한 번에 commit한다. 투구·타석 결과·교체·반이닝 경계가 나오면 새 play가
시작된다.

## 투구와 타석

- 2스트라이크 뒤 일반 파울은 count를 유지하지만 번트 파울과 잡힌 foul tip은 삼진이 될 수 있다.
- 자동 볼·자동 스트라이크는 count에 반영하고 실제 투구 수에는 넣지 않는다.
- 이닝·타순·`N구 후` 또는 `초구 전`이 붙은 피치클락 경고는 공지 행이며, 뒤의 번호 있는 투구를
  자동 판정으로 바꾸지 않는다. 원천이 볼·스트라이크 위반을 직접 기록했거나, 투구 위치가 없는
  단독 경고 뒤 ID 없는 동일 판정 행이 이어진 경우만 자동 판정 후보다.
- `no_pitch`도 실제 투구 수에 포함하지 않는다.
- `sourcePitchId`는 Naver가 제공한 경우에만 있고 고유키가 아니다. tracking은 `trackingId`로 식별한다.
- tracking의 `sourcePitchOrdinal`은 Naver PTS `ballcount` 증거 값이며 실제 PA 투구 순번과 다를 수
  있다. compiler는 이를 count 권위나 link ordinal 검증에 사용하지 않고 실제 순번을 PA lifecycle에서
  계산한다.
- 4볼 또는 3스트라이크 뒤 결과 없이 다음 투구가 오면 잘못된 타석 경계로 차단한다.
- 원천 투구 누락 때문에 count와 결과가 다르면 finding을 남기되 확인 가능한 후속 원장 행은 버리지
  않는다.

결과 없이 타석이 끝나면 임의 결과를 만들지 않고 partial PA로 남긴다. 실제 투구는 lifecycle에
포함하지만 공식 PA·타수와 투수 상대 타자 수에는 포함하지 않는다.

- `plate_result`: 결과가 있는 완료 PA
- `third_out`: 진행 중 타석에서 주루사 등으로 3아웃
- `walk_off`, `called_game`, `forfeit`: 경기 상황 종료 partial
- `source_boundary`: 3아웃 미만 원천 반이닝 불연속
- `end_of_document`: 문서 끝까지 결과·경계가 없음

다음 반이닝 시작 시 계산 아웃이 3이면 열린 타석도 정상 `third_out` partial로 닫는다. 계산 아웃이
3 미만일 때만 `source_half_incomplete`를 만든다. 다음 공격 이닝의 같은 타자는 0-0의 새 PA다.

## 타석 결과 기본 movement

compiler가 유일하게 결정할 수 있는 타자 상태는 다음과 같다.

- 1·2·3루타: 타자 1·2·3루
- 홈런: 타자 득점
- 볼넷·고의4구·사구·방해·야수선택·실책 출루: 타자 1루
- 범타·삼진·희생번트·희생플라이: 기본 타자 아웃
- 병살·삼중살: 결과에 명시된 직접 아웃과 실제 연결 주자 행을 사용
- `other`: 원천에서 확정된 정보 외에는 파생하지 않음

낫아웃, 희생타 실책, 병살 중 타자 생존 같은 예외는 `batterDestination`으로 기본값을 바꾼다.
낫아웃 출루는 2아웃이거나 투구 시점에 1루가 비어 있을 때만 허용한다. 희생타는 기록 분류이고
실제 생존 여부와 독립적이다.

타구 유형 `ground_ball`, `fly_ball`, `line_drive`, `popup`과 번트 여부는 분석 사실로 보존하지만
아웃·득점을 중복 결정하는 movement가 아니다. `outKind`는 득점 규칙에 필요한 최종 movement
속성으로 compiler가 결과와 명시적 예외에서 정한다.

## 제3아웃과 득점

- 제3아웃이 force out, force appeal 또는 타자주자가 1루에 닿기 전 아웃이면 그 play의 득점을
  인정하지 않는다.
- 그 밖의 time play는 홈 도착이 제3아웃보다 먼저면 득점한다.
- appeal로 선행 주자가 제3아웃이면 그보다 후행 주자의 득점은 인정하지 않는다.
- 수비가 유리한 apparent fourth out을 선택한 경우 `supersedesThirdOut`으로 득점을 재판정한다.
- 제3아웃 후 최종 outs는 3이고 베이스는 비운다.

제3아웃이 먼저 확정된 play에서는 그 시점 이후의 안전 도착 베이스를 최종 점유로 검증하지 않는다.
반이닝 종료와 함께 베이스가 비워지기 때문이다. 다만 제3아웃 전 이동, 모든 출발 위치, 아웃 순서와
득점 시간은 그대로 검증한다.

원장 행의 실제 순서를 득점 시간 판정에 사용한다. 제3아웃 뒤 안전 진루를 발명하지 않으며, 명시된
후행 appeal은 규칙에 따라 검증한다.

## 교체와 책임

- 투수 교체 시 2-0, 2-1, 3-0, 3-1, 3-2에서 끝난 볼넷은 이전 투수 책임으로 귀속한다.
- 2스트라이크에서 대타가 들어와 삼진이면 삼진은 교체 전 타자에게 귀속한다.
- 타석 시작 전 대타 교체는 열린 타석 count와 책임 기록을 바꾸지 않는다.
- 대주자는 교체 전 주자의 책임 투수를 승계한다.
- fielder's choice로 책임 주자가 아웃되면 KBO 9.16(g)의 prior-pitcher 책임 슬롯을 보존하며, 같은
  주자의 후속 다단계 이동과 득점까지 그 책임을 이어간다.
- 고의4구는 볼넷 합계와 고의4구를 각각 1개씩 증가시킨다.

선수 교체는 명시적 ID를 우선하며 동명이인을 이름만으로 추정하지 않는다. 이미 등판 중인 투수가
타순에 들어오는 DH 해제는 새 투수 교체로 중복 처리하지 않는다.

## 관측과 공식 기록

야수선택 책임 슬롯은 주자별 출발 위치와 마지막 이동으로 계산한다. 중간 진루를 별도 생존 주자로
세지 않으며 같은 플레이에서 득점한 주자도 책임 승계에 포함한다.
진루하지 않고 같은 베이스에 남은 생존 주자도 책임 슬롯을 승계한다. 이를 위해 원장이나 movement에
가짜 진루를 추가하지 않으며, 전체 이동 검증에 성공한 경우에만 최종 base occupant의 책임을 갱신한다.
실패한 atomic play는 이 책임 변경도 반영하지 않는다.
포스 병살(`double_play`와 기존 주자의 `outKind: force`)에서도 같은 책임 슬롯을 승계한다.
타자가 함께 아웃되더라도 생존 주자의 후속 득점에 이전 투수의 책임이 남는다. 비포스 병살은 이
추가 승계의 대상이 아니다. 근거는 [공식 야구규칙 9.16(g) 주석](https://content.mlb.com/documents/2/2/4/305750224/2019_Official_Baseball_Rules_FINAL_.pdf#page=144)의
개별 주자 대신 남긴 주자 수에 대한 책임 원칙이다.

`administrative.called_game`은 종료 경기의 마지막 반이닝에 명시적으로 선언되고 이후 실제 진행이
없을 때 연장전도 닫는다. 반이닝 없는 선언이나 이후 투구가 있는 선언은 차단한다. partial PA의 투구는
유지하고 공식 PA에는 포함하지 않는다. 2스트라이크 번트 파울 다음 삼진 결과가 확인된 terminal pitch만
제공자의 strike=2 표기를 warning으로 비교한다. 원본 관찰값과 다른 상태 필드의 차단 비교는 유지한다.

Naver 관측은 해당 행이 어느 시점의 상태를 나타내는지 확실한 동기화 지점에서만 비교한다. 투구 행은
다음 플레이 결과가 미리 반영된 snapshot이 섞이므로 balls·strikes만 비교한다. 타석 결과와 연결
주자 play는 전체 play의 마지막 상태 변경 행에 `observedStateAfter`가 있을 때만 그 상태에서
outs·bases·score를 비교한다. 마지막 행에 관측이 없으면 앞선 주자 행의 중간 snapshot을 역탐색해
최종 상태와 비교하지 않는다. 독립 다중 주자 play에도 같은 경계를 적용한다. 반이닝·타석 머리글,
교체, 판독·공지·footer 같은 비상태 행은 일반 상태 검증 기준으로 사용하지 않는다. 제3아웃 행에서
정리 전 잔루 snapshot이 남는 경우에는 종료된 base 비교를 생략하고 outs와 score는 계속 비교한다.

끝내기 잔루도 같은 관측 경계를 적용한다. 문서가 `final`이고 정규 예정 이닝 이상의 말 공격에서
계산된 홈 점수가 앞서며 마지막 상태 변경 행 뒤에는 판독·안내만 남은 경우, 해당 타석 play 또는
독립 주루 play의 bases 관측은 비교하지 않는다. 점수·아웃, 독립 주루의 볼카운트, 공식 기록 검증은
유지한다. 원문 관측값과 계산된 잔루는 보존하고 누락된 이동을 합성하지 않는다. 누락·중복 점유 등
이동 자체가 유효하지 않으면 끝내기 점수도 반영하지 않는다.

`hit_by_pitch` 투구는 실제 투구 수에는 포함하지만 볼카운트를 증가시키지 않는다. Naver가 사구
종결 표기로 해당 투구 snapshot의 balls를 `4`로 보내더라도 그 balls 값은 count 동기화에 사용하지
않는다. 과거 원장처럼 같은 타석의 명시적 `hit_by_pitch` 결과에 직접 이어진 투구가 `ball`로
남아 있어도 같은 balls 검증 경계를 적용한다. 같은 행의 strikes는 계속 비교하고, 일반 볼넷이나
다른 count 불일치는 기존처럼 차단한다. 이 예외는 투구 call·원천 관측값을 수정하거나 계산 상태에
주입하지 않는다.

한 동기화 지점에서 여러 필드가 다르면 하나의 `source_observation_mismatch`에 detail로 모은다.
불일치 구간은 balls·strikes·outs·score·각 base 필드별로 관리한다. 같은 필드의 차이는 후속 행마다
복제하지 않고 최초 finding 하나를 유지하며, 실제로 다시 비교해 일치한 필드만 구간을 닫는다. 따라서
투구 행의 count 일치가 그 행에서 비교하지 않은 score·outs·bases 불일치를 지우지 않는다.

`final` 경기에서는 양 팀 점수를 모두 가진 마지막 source 관측을 별도의 종료 checksum 후보로
사용한다. 그 뒤에 source 홈런이나 득점 주자 행이 없어 최종 관측임을 확인할 수 있을 때만 수동 보정
행까지 모두 적용한 compiler 최종 점수와 score 필드만 비교한다. 종료 점수가 맞더라도 앞서 발견한
count·주자·outs·score 불일치를 일괄 해제하지 않으며, 다르면 기존
`source_observation_mismatch`에 원정/홈 점수 detail을 남긴다. final이 아니거나 양 팀 점수가
완전하지 않거나 뒤의 source 득점 가능 행 때문에 최종 관측임을 확인할 수 없으면 종료 점수를
합성하거나 추측하지 않는다.

공식 타자·투수 기록은 제공된 필드만 계산 기록과 비교한다. Naver가 제공하지 않은 2루타·3루타·
사구·희생타 등을 0으로 만들지 않는다. 득점 play에 명시적 타점이 없으면 기록원 판단을 완전히
재구성할 수 없으므로 공식 타점 차이를 차단 finding으로 만들지 않고 warning으로 남긴다. 자책점은
임의 계산하지 않고 공식 값만 보존한다.

공식 기록에 양수인 비교 대상 계수가 있는데 해당 선수의 계산 행이 없으면
`official_batter_record_missing` 또는 `official_pitcher_record_missing` blocking을 남긴다.
제공된 양수 필드를 한 finding의 detail로 모으며 실제값은 미계산을 뜻하는 `null`이다.
전부 0인 행, 생략된 선택 필드와 자책점만 있는 행은 이 규칙으로 차단하지 않는다.
동명이인도 선수 ID를 기준으로 비교하고 이름으로 계산 행을 대신 연결하지 않는다.
