# 새 경기·시즌의 분석 자동 반영

PostgreSQL 적재 성공 뒤 공식 경기 분류와 필요한 모델을 자동으로 갱신한다. 서버 시작 시와 이후 1분마다 현재 봉인 revision을 대조하므로 종료 직전에 완료된 적재도 빠뜨리지 않는다. 적재가 진행 중이면 기다리고 같은 시즌의 여러 경기를 묶어서 처리한다. 적재 후 확인은 10초 뒤 시작하며 화면은 15초마다 반영 상태를 읽는다.

## 권위와 보존

현재 봉인된 경기의 ID·revision·document hash와 분류 dataset hash로 변경을 확인한다. 교정 원장, 최초 원본, source bundle, 기존 sealed revision과 fact는 수정하지 않는다. 수동 교정의 재수집·재파싱·재적재도 수행하지 않는다. 분류 정책이 바뀌거나 현재 정책으로 확인한 기록이 없으면 첫 자동 점검에서 공식 일정을 다시 가져온다. 현재 정책으로 확인한 dataset은 이후 추가 적재 때 먼저 재연결하며, 미분류 경기가 남으면 KBO 공식 일정을 가져온다. 월별 일정과 연결되지 않은 적재 경기 날짜는 KBO 게임센터에서 확인한다. 게임센터의 명시적 올스타 유형을 사용하고, 순위 결정전은 별도 공식 공지에서 확인한 경기 ID와 대조한 뒤 포스트시즌으로 분류한다. 연결은 collection의 제공자 ID·날짜 검증을 따르며 모호한 연결을 추측하지 않는다.

기존 일정에 연결되는 적재 경기가 0건이어도 새 일정을 가져온다. 새 일정의 채택 여부를 검사할 때는 기존 일정과 직접 연결된 경기와, 뒤늦게 적재되어 정확한 ID와 날짜로 현재 분류된 경기를 모두 확인한다. 이 중 한 경기라도 새 일정에서 빠지면 기존 일정을 유지한다. 모의 실행에도 같은 검사를 적용한다.

`0013_late_import_competition`은 기존 일정 채택 시 아직 없던 경기라도 정확한 제공자 ID와 날짜가 일치하면 분류를 읽도록 view를 수정한다. 별칭 연결은 기존 collection 연결기와 새 dataset 채택을 사용한다. sealed dataset/fact를 변경하지 않으며 analytics contract 4와 projection version 4를 유지한다.

## 순서와 복구

공식 분류 → 적용 시즌별 여섯 모델 점검·갱신 순서다. 과거 S시즌의 추가 적재나 교정 revision은 저장된 S 이후 적용 시즌도 점검한다. 같은 원천인 모델은 유지하고, 전 시즌까지 학습·두 선행 시즌 검증·적용 시즌 평가 정책을 유지한다. 적용 시즌 자료를 같은 시즌 모델의 선택·계수에 사용하지 않는다.

모델 갱신을 시작하기 전에 영향받는 시즌마다 진행 상태를 저장한다. 앞선 시즌의 갱신을 기록한 직후 서버가 중단되어도 재시작 시 뒤에 남은 시즌을 처리한다.

현재 작업 상태는 `analysis/preparation/<season>.json`에 저장한다. `analysis/preparation/classification/<season>.json`에는 분류 정책 버전, 확인을 시작한 경기 원천 지문, 분류 dataset 지문, 완료 시각과 오류를 별도로 저장한다. 두 파일 모두 strict decode, writer lock과 atomic write를 사용한다. 공식 분류 수동 동기화가 dataset을 채택하면 같은 기록을 저장한다. 모의 실행은 기록을 쓰지 않는다. DB의 현재 봉인 자료가 재처리 대상의 권위다. 분류 실패와 잔여 미분류는 해당 시즌의 분류 시각을 기준으로 같은 원천에서 6시간 뒤 다시 확인한다. 다른 시즌이나 모델 작업은 이 시각을 갱신하지 않는다. 원천이 바뀌면 다시 처리한다. 재시작 때 분류가 끝난 시즌은 중단된 모델 작업부터 이어간다. 공식 일정에 없는 경기는 미분류로 남기며, 모델 학습에는 정규시즌으로 확인된 경기만 사용한다. 모델을 쓰는 지표는 기존 채택 기준을 통과한 모델만 사용한다.

6시간 주기 모델 점검 설정은 별도 선택이다. 이 설정을 꺼도 경기 적재 후 갱신은 수행한다. `KBO_ANALYSIS_AUTO_REFRESH` 기본값은 `true`다. 외부 호출을 차단하는 격리 E2E는 `false`를 주입하고 공식 일정 fixture를 주입한 manager/DB 통합 테스트에서 자동 경로를 검증한다.

## 화면과 시즌

GET `/api/v2/analysis/seasons`는 실제 적재된 시즌, 현재 원천 지문과 반영 상태를 반환한다. 시즌 선택·선수 탐색·구질·선구안·기간 비교에서 고정된 2025 상한을 제거한다. 분석 화면은 비교 기준으로 삼을 시즌 상태가 없으면 첫 응답을 기다린다. URL에 시즌을 명시했다면 첫 상태 확인 실패 후에도 지정한 시즌을 조회한다. 상태가 복구되면 기준 없이 시작한 분석 조회를 갱신한다. 시즌을 생략한 분석 주소는 오래된 목록을 재확인한 뒤 가장 최근 적재 시즌을 사용한다. 빈 목록은 적재 안내, 상태 확인 실패는 다시 확인 버튼을 표시한다.

각 분석 조회가 사용하는 시즌의 봉인 자료나 경기 분류 지문이 바뀌면 활성 조회가 갱신된다. A/B 기간 비교는 양쪽 시즌을 확인한다. 모델을 사용하는 조회는 적용 시즌의 모델 갱신 결과도 반영한다. 숨긴 분석이나 전체 투구를 미리 요청하지 않는다.
첫 응답의 지문은 이후 변경을 판단하는 기준으로 기록한다.
조회 중인 시즌의 지문이 바뀌면 아직 결과를 받지 못한 첫 요청도 취소하고 새로 조회한다.
브라우저 탭에 돌아오면 열려 있던 투수·타자 목록을 재사용한다. 해당 시즌의 봉인 자료나
경기 분류 지문이 달라진 것을 시즌 상태 확인에서 감지하면 목록을 다시 불러온다.

서버는 현재 경기 revision과 경기 분류 자료의 포인터를 함께 확인한다. 두 포인터 집합이 같으면
메모리의 시즌별 요약을 재사용한다. 변경을 감지하면 포인터와 요약을 같은 읽기 전용 snapshot에서
갱신한다. 반영 상태 파일은 워크스페이스 writer가 읽은 값을 재사용하고, 해당 시즌의 파일을
교체할 때 다시 읽도록 한다.

모델 관리에서는 선택기, 모델 조회, 반영 안내가 URL의 `season`을 공유한다. 선택기를 바꾸면 URL에 반영하며, 미분류 경기 안내는 상태 메시지로 제공한다.

일반 모델 적용 시즌 계약은 2020–2200, 학습 마지막 시즌은 2020–2199다. 실제 지원 여부는 기존 검증 이력·표본 gate에 따른다. 승리확률 규정은 확인한 2022–2026만 지원하고 그 이후 규정은 미지원으로 표시한다. 분석용 스트라이크존은 경기 시즌에 적용할 수 있는 가장 최근의 기준을 사용한다.
