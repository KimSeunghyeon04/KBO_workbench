# 과거 시즌 모델 학습·적용 검증

2026-09-21. 기간 정책과 메타데이터 계약 결정은 [모델 운영 설계](model-management.md)를 따른다.

## 구현

- 2020–2025 상태 조회, 일반 모델 2023–2025 학습, 규정·검증 이력이 부족한 승리확률 시즌 제외.
- 적용 시즌 직전 두 시즌 검증, 각 검증 이전 자료로 전처리·계수 적합, 적용 시즌은 선택 후 평가.
- 시즌별 자동 갱신과 시즌을 포함한 멱등성, 하나의 worker, 원천·기반 모델 재확인 뒤 원자적 공개.
- strict legacy 작업/설정은 2025로 읽고 새 저장은 명시적인 version 2. 모델·DB 계약은 유지.
- 학습 기간·검증 연도·평가 연도가 맞지 않는 파일은 사용하지 않는다. 기존 API의 시즌별 파일 선택을 유지.
- 카운트 후보의 같은 기간 RE24 사전표를 재사용한다. 승리 규정의 작은 모듈을 분리해 기간 정책과
  관측 수집·RE 계산 사이에 순환 import가 생기지 않게 했다.

## 검증 범위

단위/API/UI 863개, PostgreSQL 72개, 격리 Compose E2E, lint/format/typecheck/schema/build 통과.
모듈 분리 뒤 architecture·승리확률·기간 검증 31개도 통과했다. E2E는 실제 worker로 2023년용
5개와 2025년용 6개 모델을 저장하고, 시즌 분리·미지원 UI·중복 요청·재시작·기존 복구 흐름을 검증했다.

미래 시즌 label·코스·구속을 바꿔도 과거 시즌의 전처리·계수·선택이 변하지 않는지 확인했다.
DB 통합 테스트는 이후 시즌의 경기·분류·신장이 과거 범위의 원천/캐시 해시에 영향을 주지 않는지
검증한다. 미지원 강제 학습, 잘못된 기간의 worker 결과·파일, 시즌이 다른 동일 요청 ID를 거부한다.

compiler 평균 9.083ms/p95 11.084ms, replay 평균 1.178ms/p95 1.764ms로 기존 한도를 통과했다.
실데이터 학습과 동시에 측정했으므로 이전 측정치와 속도 개선·악화 비교에는 사용하지 않는다.

## 실데이터 실행

기존 검증 DB의 소유 label/ID를 확인하고 모든 연결을 읽기 전용으로 고정했다. 원천·봉인 fact를
수정하지 않고 새 `analysis/validation/20260921-historical-models/workspace/`에 기간별 모델을 저장했다.
시즌과 모델을 순서대로 실행하며 입력·적합·공개 시간 및 프로세스 RSS를 기록한다.
최종 결과와 적용 점검은 같은 디렉터리의 `training.json`, `application.json`에 보존한다.
일부 학습과 품질 게이트가 동시에 실행됐으므로 시간은 관측값이며 처리량 상한이 아니다.

| --------- | -------------- | -------------- | -------------- | -------------- | ------------- |
| 2023      | 2020–2022      | 2021, 2022     | 5개            | 226.0초        | 2.76GiB       |
| 2024      | 2020–2023      | 2022, 2023     | 5개            | 349.8초        | 3.19GiB       |
| 2025      | 2020–2024      | 2023, 2024     | 6개            | 521.2초        | 3.83GiB       |

2025 승리확률의 최종 학습 범위만 2022–2024다. 2023·2024 승리확률은 선행 검증 이력 부족으로
학습하지 않았다. 2020–2022는 일반 모델도 제공하지 않고 기존 관측 통계를 사용한다.

2023·2024의 RE24는 pooled, 카운트 기대 득점은 shrinkage 100을 선택했다. 구질 기대 효과는
스윙·헛스윙·루킹 모두 코스 포함 모델을 채택했고 매치업도 세 항목 모두 채택했다. 구장 효과는
홈런만 채택했으며 득점 효과는 검증을 통과하지 못했다. 갱신 완료와 개별 지표의 채택을 구분한다.
2025의 여섯 모델 hash는 이번 코드로 다시 학습해도 기존 운영 모델과 모두 같았다.

각 시즌 최다 투구 투수와 그 투수의 최다 상대 타자, 시즌 첫 경기를 골라 구질·매치업·구장·
RE24·카운트 기대 득점의 실제 적용을 확인했다. 15개 응답 모두 모델 적용 상태가 준비됨이었고,
다른 적용 시즌의 구질 모델을 전달하면 모델을 제외하는지도 확인했다. 구질 적용 표본은 각각
2,842/2,988구, 2,983/3,124구, 2,757/3,037구였다. 이는 선택한 투수의 표본이며 시즌 전체
지원률을 의미하지 않는다.

## 운영 반영

2026-09-21 오전 8시경 API/web 이미지를 교체하고 운영 갱신 API로 2023·2024 모델을 순차 학습했다.
두 작업은 각각 232.4초, 320.8초에 성공했고 모델 hash 10개가 별도 검증 환경과 모두 일치했다.
같은 요청 ID 재전송은 같은 완료 작업을 반환하며 다른 시즌으로 재사용하면 409였다.
2025 모델 6개와 자동 갱신 꺼짐 설정은 유지했다. 작업 결과는
`analysis/deployment/20260921-historical-models/http-jobs.json`에 있다.

세 시즌의 실제 분석 API 응답 15개를 strict decode하고 위 검증 환경의 전체 응답 hash와 비교했다.
모두 일치했으며 모델 관리 화면의 2023/2024 최신 상태, 학습·검증 기간, 2020 미지원 안내와
390px 화면의 가로 넘침 없음도 확인했다. 브라우저 console과 배포 이후 API 로그에 오류가 없었다.
자동 갱신은 임의로 활성화하지 않았다. 사용자가 적용 시즌을 골라 개별적으로 켤 수 있다.

배포·학습 전후 current/active 원장 파일 11개와 sealed revision 4,693개의 document/projection hash가
동일하다. migration head `0012_competition_game_links`는 유지했고 DB/API/web은 healthy다.
증거는 같은 배포 디렉터리의 `http-application.json`, `integrity.json`에 보존했다.
배포 전 실행 이미지의 복구용 태그를 남겼으며 DB 복구나 원장 교체는 수행하지 않았다.
