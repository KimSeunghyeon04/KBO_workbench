# 투수 운용 조건 비교 검증

2026-09-21. 계산 정의 1과 표본 문턱은 [투수 운용 설계](features/12-pitcher-workload.md)에 고정했다.

## 구현과 권위

기존 등판 화면에 지연 조회하는 `조건을 맞춘 운용 비교` 패널을 추가했다. 관측 휴식, 이전 3/7일
투구량, 경기 내 투구 순번, 동일 타자 대면별 구속·스윙률·헛스윙률을 비교한다. 같은 투수/시즌의
등판 역할·구종·타석·카운트 공통 셀을 같은 가중치로 맞추고 경기 단위 95% 구간을 계산한다.
원 집계·공통 표본·제외·불확실성을 구분하며 표본 부족이나 재표집 불안정은 수치를 보류한다.

등록 역할을 필수로 둔 초기 실자료 점검에서는 표본 투수의 모든 투구가 제외됐다. 이 자료의
starter/P 근거가 없기 때문이었다. 등록 정보가 없을 때는 봉인된 실제 투구 순서에서 확인한
첫 투수/후속 투수라는 별도의 관측 역할을 사용했다. 공식 선발/구원으로 추정하지 않으며 기존
등판 API의 등록 역할은 미상으로 유지한다. 역할 근거별 표본을 새 응답·화면에 표시한다.

새 계산은 contracts → 기능별 repository → 기존 분석 worker → 순수 game-core → 패널 경로다.
두 소비자가 공유하는 날짜 창과 current 경기/등판 조회만 추출했다. 기존 등판 응답의 의미와
원천 hash를 유지하고, 새 모델·범용 registry·서비스·DB migration을 추가하지 않았다.

## 검증

- architecture 17개를 포함한 단위/API/UI 873개와 기존 품질 게이트가 통과했다.
- 격리 PostgreSQL 74개가 통과했다. current revision, 실제 투구 순번을 필터보다 먼저 계산하는지,
  자동 판정 제외, tracking 누락, 반복 대면, 후속 투수, 미래 기록 불변성과 분류 범위를 검증했다.
- 격리 Compose E2E가 패널 열기·로컬 지표 전환·소표본 보류·1440/390px 레이아웃과 기존
  import/replay/교정/재시작/backup/restore를 통과했다. 이후 SQL 최적화는 DB 테스트와
  실자료 응답 hash로 다시 검증했다.
- 합성 자료는 구종 구성 차이가 표준화 후 사라지는지, 같은 경기의 공통 충격을 짝지어 재표집하는지,
  미래·입력 순서 불변성, 역할의 근거 구분, 분모와 제외 합계, 불안정한 재표집의 보류를 검증했다.
- compiler 평균 9.062ms, p95 11.684ms로 기존 10/25ms 한도를 통과했다.

## 실제 자료와 비용

198개 지표·집단 비교 중 72개가 제공 가능하고, 124개는 공통 표본 부족, 2개는 재표집 불안정이었다.
문턱을 실자료 결과에 맞춰 낮추지 않았다. 장기 등판 투수의 경기 내/대면 비교와 다등판 투수의
휴식/누적량 비교에 주로 표본이 있었다. 기존 등판 응답 6개의 전체 hash는 배포 전 운영 응답과 같았다.

초기 실행계획은 대면 window를 3,037회 다시 실행하고 약 233만 쌍을 조인 조건에서 제외했다.
대면 회차와 투구 연결을 먼저 한 번 계산하도록 집계 단계를 고정했다. 최적화 전후 새 응답 6개의
hash도 모두 같았다. 같은 투수의 반복 조회 p95 관측값은 534ms에서 190ms로 줄었다.

별도 프로세스에서 가장 큰 입력 2,696셀(2024/53546)을 다시 측정했다. 최초 요청은 worker 시작을
포함해 1,647.5ms, 이후 30회 p50 184.4ms/p95 217.4ms였다. 25ms 간격으로 관측한 전체 Node
프로세스 RSS 최대는 약 439MiB였다. 부모와 공유 worker를 포함하며 DB 메모리·HTTP·브라우저
렌더링은 제외한다. 동시 검증 작업이 있었으므로 서비스 지연 보장이나 정확한 순수 알고리즘 비용으로
해석하지 않는다. 전체 시즌 원시 궤적이나 원장을 새 worker로 복제하지 않는다.

실행 결과·실행계획·반복 측정은 `analysis/validation/20260921-workload-comparison/`의
`real-data.json`, `query-plan-before.json`, `query-plan-jit-off.json`, `benchmark-final.json`에 보존했다.

## 운영 반영 검증

2026-09-21 운영 API와 웹을 교체하고 준비 상태를 확인했다. 새 비교 응답 6개는 격리 검증 환경의
전체 hash와 일치했고, 기존 등판 응답 6개도 배포 전과 같았다. 잘못된 날짜·미지원 쿼리는 400으로
거부하고, 기록이 없는 투수는 빈 표본과 비교 보류 상태를 정상 반환했다.

실제 브라우저에서 패널 열기, 구속·헛스윙률 전환, km/h·%p 단위, 공통 표본 부족 시 수치 보류와
표의 가로 스크롤을 확인했다. 브라우저 경고·오류와 배포 이후 API의 경고·오류·5xx 기록은 없었다.

2023–2025 모델 16개의 hash, current/active 파일 11개의 hash, 4,693개 sealed revision의
document/projection hash를 유지했다. migration head는 `0012_competition_game_links`이고
API·웹·DB는 모두 healthy였다. 자동 모델 갱신의 비활성 상태도 유지했다. 새 기능은 조회 시 계산하며
원장·봉인 fact·학습 모델을 수정하지 않는다. 이전 서비스로 복귀할 수 있는 이미지도 별도로 보존했다.

운영 HTTP 대조와 무결성 기록은 `analysis/deployment/20260921-workload-comparison/`의
`http.json`, `http.log`, `integrity.json`, `deployment.json`, `api.log`에 보존했다.
