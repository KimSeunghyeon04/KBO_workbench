# A05. 투수 변화 감지

선행 조건: A03의 구질 표본과 같은 기준의 기간 비교. 부상·피로 진단 기능은 포함하지 않는다.

## 첫 화면

구종별 경기 평균·분산·사용률과 최근 3등판 대 이전 5등판의 차이를 보여준다.
범위는 분석 종료일 이전의 완료된 등판으로 고정한다. 등판은 game identity 단위이며 더블헤더는
순서를 확인할 수 있을 때만 정렬하고, 날짜만 같은 경기를 임의 ID 순서로 선후 관계로 만들지 않는다.

## 계산 정책

- 구속은 원 관측 단위, 구질은 동일 시즌 기준의 보정 좌표, 사용률은 실제 투구 수 기준으로 비교한다.
- 최근/이전 창은 겹치지 않는다. 해당 구종이 없던 경기는 구질 평균을 0으로 채우지 않는다.
- 기간 요약은 투구 가중 평균, 변화의 불확실성은 경기 단위 재표집으로 계산한다.
  경기 동일 가중 결과를 함께 확인할 수 있으나 기본값과 혼합하지 않는다.
- 소표본 상태의 첫 기준은 비교 구간 각각 해당 구종 30구 미만 또는 관측 3경기 미만이다.
  표시는 유지하되 ‘확인 가능한 변화’ 판정은 제공하지 않는다. 이 수치는 공식 자격 기준이 아닌
  초기 제품 기준으로 문서·계약에 명시하고 검증 뒤 바꿀 수 있다.
- 보정 적용 여부·구장 구성·카운트·타석 좌우 구성의 변화도 같이 보여준다. 조정하지 않은 비교는
  조건 구성 변화가 포함된 관측 차이로 설명한다.
- 첫 버전은 통계적 경보를 자동 발송하지 않는다. 사용자가 선택한 구종·기간의 차이와 표본을 보여준다.
  여러 구종/선수를 한꺼번에 검사하는 경보는 다중 비교와 오탐 검증 후 별도 기능으로 결정한다.

## 구현 순서

1. [x] `contracts/pitcher-changes.ts`에 비교 창·등판 순서 상태·지표별 사용 수·차이 계약 추가.
2. [x] `game-core/pitcher-changes.ts`에 창 분할과 요약 함수 추가. 난수는 seed로 주입.
3. [x] `persistence/pitcher-changes-repository.ts`는 A03의 같은 계산 표본을 재사용하도록 필요한
       공개 입력만 추출. 기존 화면 응답 전체를 내부 분석 입력으로 사용하지 않는다.
4. [x] `/api/v2/analysis/pitcher-changes/:pitcherId`와 투수 화면의 변화 탭 연결.
5. [x] 3/5등판 요약부터 측정하고, 경기 내 투구 수 구간(1–25/26–50/51–75/76+) 비교를 후속 추가.

## 검증과 완료 조건

고정된 구질에서 잡음만 있는 경우, 알려진 구속 변화, 구장만 바뀐 경우, 희소 구종,
비시즌 공백, 보정 불가 구간과 더블헤더 순서 미상을 테스트한다.
분석 종료일 이후 투구를 추가해도 해당 종료일의 입력·결과가 바뀌지 않는 경로를 별도로 검증한다.
현재 시즌 전체 기준의 탐색 결과와 as-of 계산을 구분하며, 후자의 기준도 종료일 이전만 사용한다.
차이의 단위·표본·비교 창을 근거 경기까지 재현할 수 있으면 완료한다.

조회 개선: fresh snapshot의 종료일·경기 종류·원천 해시로 보정과 포심 기준 파일을 확인한다.
둘 다 준비되어 있으면 대상 투수만 조회한다. 기준 누락 시에만 필요한 시즌 표본을 읽고 계산 전에
DB 연결을 반환한다. 완료 경기 전용 기준은 해시에 `finalOnly`를 포함해 다른 기준과 섞이지 않는다.

원천 궤적 VAA/HAA 패널도 같은 종료일과 완료 경기 범위를 사용한다. 구종별·경기별 각도와
통과 코스를 함께 표시하며 보정된 구질의 최근 3/이전 5등판 변화 판정에 원천 각도를 섞지 않는다.
각도 정의와 제외 기준은 [A03](03-pitcher-profile.md)을 공유한다.
