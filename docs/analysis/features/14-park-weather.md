# A14. 구장과 날씨 환경

선행 조건: A01·A02. 움직임 연결은 A03. 구장 측정 편향 보정과 득점/홈런 환경 효과는 별개다.

2026-09-21부터 2023–2025 적용 시즌을 지원하고 직전 두 시즌에서 후보를 비교한다.
기간별 원천과 학습·평가 분리는 [모델 운영 설계](../model-management.md)를 따른다.

## 1단계: 구장 효과

첫 지표는 구장별 득점/타석·홈런/타석과 홈/원정 비교다. 상대 공격·수비 팀, 시즌, 월을 고려한
축소 모형을 후속 비교한다. 선수 구성 차이를 포함하는 단순 평균을 순수 구장 효과라고 부르지 않는다.
돔도 구장 효과 비교에는 포함할 수 있으며 야외 날씨 분석에서만 제외한다.

| 결과 | 최초 모형과 노출량                                                               |
| ---- | -------------------------------------------------------------------------------- |
| 홈런 | 팀·경기별 HR 수와 PA 노출량의 Poisson 기준, 구장·공격팀·상대팀·시즌·월 항        |
| 득점 | 팀·경기별 득점 수와 공격 이닝 노출량의 Poisson 기준; 과산포를 확인해 대안과 비교 |

부분 이닝을 아웃/3으로 치환한 노출량은 끝내기 영향을 받으므로 첫 득점 모형은 완결 반이닝
단위로 적합하고 제외 범위를 표시한다. 홈런/PA 모형과 득점/완결 반이닝 모형의 대상이 다름을 명시한다.
구장 효과는 식별 가능한 합계 제약과 정규화를 사용하고 리그 기준 100의 상대값·표본·불확실성을 제공한다.
홈팀과 구장 공선성이 커 식별이 안 되면 수치를 확정하지 않는다. 희소 구장은 리그로 축소하고 원 표본을 남긴다.

기존 구장 보정의 park mapping을 출발점으로 읽되, 환경 효과용 구장은 실제 시설과 기간을 구분한다.
같은 구장명이 다른 시설/시기를 가리키는 경우 확인된 근거 없이 합치지 않는다. 추정으로 alias를 늘리지 않는다.
기존 무브먼트 보정 계수를 홈런 보정 계수로 재사용하지 않는다.

## 2단계: 선택적 날씨

Open-Meteo ERA5의 기온·상대습도·지상기압·풍속을 구장 좌표와 시간으로 받는다.
좌표는 검토된 구장별 소규모 참고자료로 고정하며 지원 안 되는 구장은 제외한다.
첫 구현은 확정된 경기 시작 시각의 가장 가까운 시간 자료를 사용하고 매칭 오차를 기록한다.
시각 미상·순연으로 예정 시각만 남은 경기는 시간별 분석에서 제외한다. 일별 분석은 별도 값으로 표시한다.

야외 구장에서 같은 구장·시즌·월·선수/팀 조건 아래 날씨와 구속·구질·홈런의 관계를 탐색한다.
격자 풍속을 구장 내부 바람으로 단정하지 않고, 구장 방향 정보가 없는 상태에서 순풍/역풍으로 변환하지 않는다.
날씨 모형은 첫 구장 모형에 추가했을 때 시간 검증의 오차가 줄어드는지를 평가하고 인과 효과로 설명하지 않는다.

날씨 취득이 별도 계약이나 많은 수작업을 요구하게 되면 2단계는 제외한다. 1단계 구장 분석은 계속 제공한다.

## 구현 순서

1. [x] `contracts/park-environment.ts`, `persistence/park-environment-repository.ts`에 단순 집계부터 추가.
2. [x] `game-core/park-environment.ts`의 구체적 적합·평가와
       `server/maintenance/train-park-environment.ts` 추가. 기존 보정 학습을 수정하지 않음.
3. [x] `/api/v2/analysis/park-environment`에서 원 집계·조정값·표본·훈련 기간을 구분해 제공.
4. 제외: 확정 실제 시작 시각이 없어 날씨 adapter/repository/workspace를 추가하지 않음.
5. 제외: 날씨 취득 작업. 구장 API는 외부 취득을 하지 않음.
6. [x] 구장 화면에 적용 가능한 경기 수와 시설 미확인/불충분 표본을 표시. 날씨 화면은 제외.

## 검증과 완료 조건

홈/원정 팀 교체, 공유 구장, 시설 변경/alias 불명, 희소 구장, 적은 원정 표본,
3아웃 미완료·끝내기·돔·시각 미상·KST/UTC 경계·ERA5 null/응답 실패를 검증한다.
Poisson은 validation deviance와 실제 집계 오차를 단순 구장 없는 기준과 비교하고 과산포를 보고한다.
같은 표본에서 날씨 추가 전후를 비교하고 효과가 없으면 날씨 설명 모형은 채택하지 않는다.
기술 통계 또는 채택된 조정값이 근거 경기·dataset hash까지 재현되면 해당 단계 완료다.

## 구현 범위와 확정된 제외

A14a의 기술 통계, 전용 학습 CLI, 모델 파일, API와 `/analysis/park-environment` 화면을 구현했다.
`analysis:train-park-environment --through 2024 [--dry-run]`으로 학습하며 GET에서 재적합하지 않는다.
같은 snapshot의 typed PA와 atomic half 상태를 각각 먼저 집계해 한 경기·공격팀당 한 행을 만든다.
홈런은 PA 노출량, 득점은 정상 9이닝 경기의 1–8회 완결 반이닝 노출량을 사용한다. raw 경기
득점/PA와 이 득점 모형의 분모가 다름을 표시한다. 실제 홈·원정 수치와 근거 revision을 제공한다.

구장 없는 Poisson λ=1 기준에 대해 구장 포함 Poisson/negative-binomial의 λ=0.1/1/10을 비교한다.
NB 과산포는 훈련 Poisson 잔차에서만 추정한다. 공격팀·상대팀·홈 여부·시즌·월을 통제하고,
미래 시즌은 마지막 훈련 시즌의 절편을 고정 사용한다. 새 팀/구장/월은 미지원이다. 두 검증
시즌의 deviance 개선과 경기 bootstrap 차이 95% 상한<0을 모두 요구한다. 최종 평가 자료를
바꿔도 훈련 계수가 바뀌지 않는다. 모델이 채택되어도 원 정보행렬이 식별되지 않거나 해당
구장이 30경기/공격팀 4개 미만이면 조정값을 공개하지 않는다. 상대값은 구장 효과의 기하평균
100으로 정규화한다. 게임 단위 sandwich 구간은 고정한 ridge/과산포의 조건부 불확실성이다.
역행렬·경기 score를 구장마다 다시 계산하지 않고 적합 한 번당 재사용한다.

동명 대전 구장은 2025년 이전/이후 시설을 분리한다. 근거는
[KBO 2025 개막 안내](https://www.koreabaseball.com/MediaNews/Notice/View.aspx?bdSe=11564)다.
다른 미확인 별칭은 임의 연결하지 않는다. 이 시설 identity만 무브먼트 기능과 공유하며
측정 편향 계수와 득점 환경 계수는 별개다.

A14b 날씨는 이번 구현에서 제외한다. 현재 원장에 있는 `scheduledAt`은 예정 시각이며 확정된
실제 경기 시작 시각을 제공하지 않는다. 예정 시각을 실제 시각으로 바꾸거나 많은 수작업을
추가하지 않는다는 자료 범위 조건을 적용했다. 따라서 weather adapter·빈 날씨 화면·임의
날씨 대체값을 만들지 않았다. 시간 매칭 조건이 검증된 자료가 생기면 별도 범위로 재검토한다.
