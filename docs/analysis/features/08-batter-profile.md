# A08. 타자 약점과 강점 지도

선행 조건: A04의 코스 집계·A07의 선구안 표본. 타구속도·발사각 기반 평가를 포함하지 않는다.

## 첫 화면

선택 타자의 구종·구속대·코스별 스윙/컨택/헛스윙 지도와 인플레이 결과를 제공한다.
타석 결과는 별도 표로 보여주며 ‘타자가 어느 공에 어떻게 반응했는가’와 ‘타석이 어떻게 끝났는가’를 구분한다.

## 지표와 귀속

| 표             | 단위와 분모                                                                      |
| -------------- | -------------------------------------------------------------------------------- |
| 반응 지도      | 실제 투구; Swing%=스윙/공, Whiff%=헛스윙/스윙, Contact%=(스윙−헛스윙)/스윙       |
| 인플레이 결과  | 완료 결과에 연결되는 terminal in-play 투구; 안타·장타·홈런/해당 인플레이 결과 수 |
| 종결 구종 성적 | 한 완료 PA의 종결 투구에만 연결; AB·H·TB를 함께 표시하고 종결 구종 기준임을 명시 |

볼넷·사구·삼진을 그 타석의 모든 구종 성과로 복제하지 않는다. 종결 투구가 없거나 자동 판정으로
끝난 PA는 미귀속 그룹에 보존한다. 결과 표의 합계는 공식 PA/AB 범위와 대조한다.
컨택은 파울을 포함한 관측 스윙 결과이며 타구 질을 뜻하지 않는다.

구종·구속·코스부터 시작한다. A03의 보정 무브먼트 구간을 추가할 때에도 원 중계 구종 기준을 유지하고
투수별 GMM 번호를 리그 공통 구종으로 합치지 않는다. 선택 공의 기하량만 안정적으로 연결한다.
비교군은 같은 카운트·구종·구속대·타석 좌우·코스의 다른 타자이며 A07의 최소 표본 규칙을 재사용한다.
표본 부족 구간은 빈색/미비교로 표시하고 순위를 지어내지 않는다.

## 구현 순서

1. [x] `contracts/pitch-outcomes.ts`에서 pitch 반응과 PA 결과 배열을 다른 타입으로 정의.
2. [x] `persistence/batter-profile-repository.ts`에 각 grain별 쿼리와 terminal 연결 구현.
3. [x] A04/A07과 같은 분류·비율을 공유하되 결과 귀속은 공유 grain 모듈 `game-core/pitch-outcomes.ts`에 구체적으로 작성.
4. [x] `/api/v2/analysis/batter-profile/:batterId`, 기존 선구안과 연결되는 타자 프로필 화면 추가.
5. [x] cell 선택 시 해당 투구 또는 PA 목록을 각각 제공하고 같은 revision 재생으로 연결.

## 검증과 완료 조건

한 PA에 직구 3개·변화구 2개 후 안타가 있는 fixture에서 반응은 5투구, 결과는 1PA가 되어야 한다.
자동 볼넷·무투구 고의사구·타석 중 대타·partial PA·tracking 없는 종결구를 검증한다.
원 구종 미상, 희소 cell, 무스윙 cell의 null을 확인하고 반응 표와 결과 표의 분모를 화면에서 구분하면 완료한다.
