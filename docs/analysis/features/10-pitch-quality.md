# A10. 구종 기대 효과

선행 조건: A03·A04 및 고정된 평가 데이터. 새 모형은 검증을 통과한 경우에만 화면에 제공한다.

2026-09-21부터 적용 시즌 2023–2025를 지원한다. 아래 2023/2024 검증·2025 평가 설명은
2025 모델의 예시이며, 다른 시즌은 [시즌별 기간 정책](../model-management.md)을 따른다.

## 예측 대상

첫 버전은 각각 별도 확률을 계산한다. 이를 합친 임의의 종합 점수나 외부 서비스의 Stuff+ 명칭을 사용하지 않는다.

| 결과            | 학습 표본        | 출력 의미                |
| --------------- | ---------------- | ------------------------ |
| 스윙            | 적격 실제 투구   | P(swing)                 |
| 헛스윙          | 적격 스윙        | P(whiff \| swing)        |
| 루킹 스트라이크 | 적격 비스윙 투구 | P(called strike \| take) |

HBP·IBB·번트 등 제외는 A07과 명시적으로 맞추고 수를 보존한다. 두 조건부 모형의 분모를 전체
투구로 바꾸지 않는다. 전체 투구당 기대 헛스윙은 P(swing)×P(whiff|swing)이며 따로 표시한다.
루킹은 시즌별 판정 환경을 포함한 관측 확률이고 공식 ABS 정확도 모형이 아니다.

## 비교할 모형

1. 단순 기준: 구종·카운트·타석 좌우별 과거 비율을 훈련 자료의 리그 비율로 축소한 표.
2. 구질 포함: 기준 조건 + 구속·수평/수직 구질·시간차를 입력으로 하는 L2 정규화 로지스틱 회귀.
3. 코스 포함: 같은 모형 + 정규화 실제 코스와 명시적인 코스 비선형 항.

세 모형을 같은 평가 표본에서 비교한다. 코스가 없는 공을 0, 즉 가운데 공으로 채우지 않는다.
별도 사용 가능 표본의 전체 coverage도 함께 보고한다. 구질 포함 모델도 순수 투수 능력의 인과
추정이 아니며 타자·투수 identity 효과를 첫 버전의 숨은 설명 변수로 추가하지 않는다.
pitch_call·스윙·타석 결과·사후 카운트·미래 시즌 성적은 입력 특성에서 금지한다.

## 학습과 보존

전체 설계의 시간 분할·train-only 전처리·경기 bootstrap·채택 기준을 적용한다.
훈련 종료일까지의 기준 궤적과 보정만 사용하며 유효 범위를 벗어난 새 표본에는 unsupported를 반환한다.
λ 후보, 구질 스케일과 코스 항은 validation에서 결정하고 2025 평가 전에 고정한다.
첫 후보 λ는 0.1/1/10으로 제한하고 스케일 표준화·손실 정규화 정의와 함께 manifest에 기록한다.

`analysis/pitch-quality/` 모델 파일에는 feature schema/version, 입력 범위·hash, 기준/보정 hash,
계수·스케일, 훈련 종료일, 평가 수·log loss/Brier·보정 요약과 채택 여부를 strict 형식으로 저장한다.
DB에 전체 예측 행을 복제 저장하지 않고 선수 요약은 필요한 입력에 고정 모델을 적용해 계산한다.

2. [x] `persistence/pitch-quality-repository.ts`에서 현재 fact를 고정 manifest로 읽고 결과 누수 검증.

4. [x] `server/maintenance/train-pitch-quality.ts`와 전용 workspace 보존 추가. GET에서 학습하지 않음.

## 검증과 완료 조건

확률 [0,1], 단일 클래스·완전 분리·희소 구종·누락 코스·미지원 보정·수렴 실패·파일 손상을 검증한다.
미래 행을 넣어도 훈련 전처리·기준이 변하지 않아야 한다. seed/정렬/설정이 같은 학습은 같은 결과를
재현해야 하며 부동소수점 허용 오차는 고정한다. 모형 간 비교 표본 동일성과 조건부 분모를 검증한다.
평가 gate 미달은 모델 미채택으로 완료 기록하고 성능 개선을 주장하지 않는다.

## 구현된 학습·적용 계약

`analysis:train-pitch-quality --through 2024 [--dry-run]`은 고정 snapshot에서 확정 정규시즌의
실제 투구를 읽고 DB 연결을 반환한 뒤 전용 worker에서 학습한다. 월별 조회로 단일 SQL 응답을
제한하고, worker에는 5,000행씩 전달한다. 후보별 숫자 설계 행렬은 한 fold 안에서 재사용한다.
로지스틱 손실은 표본 평균 log loss + λ·Σβ²/2이며 절편은 정규화하지 않는다. 범주 입력은
원 구종·타석과 12개 사전 카운트, 연속 입력은 구속·수평/수직 구질·시간차다. 코스 모형에는
정규화 x/z와 x²/z²/xz를 더한다. 단일 클래스·200표본 미만·20경기 미만·비수렴은 채택하지 않는다.

각 훈련 시즌의 마지막 관측일 다음 날을 기준으로 기존 84일/반감기 7일 보정을 고정한다.
그 시즌의 훈련 투구에는 해당 계수를, 다음 평가 시즌에는 마지막 훈련 시즌의 계수를 적용한다.
평균 직구 궤적·표준화·입력 최소/최대도 훈련 자료만 사용한다. 이는 시간 검증을 위한 고정
전처리이며 A03의 경기일별 갱신 계수를 대체하지 않는다. 새 구장, 미지원 계수, 새 구종/타석,
학습 입력 범위 밖, 좌표/신장 누락을 조용히 채우지 않는다. 실제 코스에는 구장 계수를 빼지 않는다.

2023/2024 검증은 동일한 완전 관측·보정 가능 표본에서 모든 후보를 비교한다. 대상별 조건부
분모를 유지하고 경기 bootstrap 1,200회/seed 73129, 구장·구종·타석별 1,000표본 이상 집단의
상대 log loss 악화 2% 한도를 사용한다. 신규 투수의 결과도 따로 기록한다. 최종 채택 후 2025
평가를 계산하며 평가 자료의 값이 바뀌어도 훈련 계수·전처리·선택이 변하지 않는 테스트가 있다.

파일에는 모델·모든 검증 후보·확률 보정 구간·전처리/계수 hash·경기 revision/document hash·
확정 분류 hash·유효 신장 hash를 보존한다. 원천이 바뀌면 모델을 미준비로 처리한다. GET에서는
학습하지 않으며 A03의 접이식 패널을 열 때만 조회한다. 미채택 대상의 기대값은 null이고 기존
관측 통계는 유지한다. 이 구현은 실제 전체 자료의 채택 결과를 미리 가정하지 않는다.
