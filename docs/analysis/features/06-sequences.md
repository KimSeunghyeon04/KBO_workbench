# A06. 배합과 궤적 조합

선행 조건: A03·A04. 첫 버전은 같은 타석의 연속 두 실제 투구만 다룬다.

## 제공할 결과

‘직구→슬라이더’처럼 앞선 구종과 현재 구종의 조합별 사용 수, 현재 공의 스윙/헛스윙/루킹 비율,
구속 차이와 실제 도착 코스 차이를 제공한다. 원천 궤적을 공통 거리면에서 비교하는 그림을 추가한다.
이를 타자의 실제 인식 시점·터널링 능력의 확정 점수·최적 배합으로 해석하지 않는다.

## 연결과 계산

- `game/revision/plate_appearance_event_id` 안에서 compiler 투구 순번으로 앞뒤를 연결한다.
  sourcePitchId나 제공자 ballcount를 순서/identity로 사용하지 않는다.
- 먼저 전체 원장 투구 순서로 쌍을 만든 뒤 구종·결과 필터를 적용한다. 필터 뒤 lag를 계산해 실제로
  떨어져 있던 공을 연속 공으로 만들지 않는다. tracking 없는 공을 건너뛰어 기하 쌍을 만들지도 않는다.
- 중간에 투수/타자 교체, 자동 판정·no_pitch가 있으면 기본 쌍에서는 제외하고 사유를 센다.
  타석이나 이닝 경계를 넘지 않는다. 상태를 바꾸지 않는 안내만 있는 경우는 허용한다.
- 쌍별 결과 분모는 두 번째 실제 투구다. Whiff는 두 번째 공의 스윙 수가 분모다.
  첫 번째 공 결과와 현재 카운트도 표시하며 단순 조합 간 결과 차이를 인과 효과로 부르지 않는다.
- 공통 거리면은 우선 제공자 좌표의 `y=23.8ft` 한 곳으로 고정한다. 홈플레이트 뒤 꼭짓점 원점 기준의
  기하 비교면이며 타자 의사결정 시점이라는 주장은 하지 않는다. 양쪽 궤적이 50ft에서 해당 면까지
  전진 교차할 때만 x/z 간격과 도착 시간차를 계산한다. 단위와 좌표 원점은 화면에 표시한다.
- 끝점 보정으로 중간 궤적까지 교정하지 않는다. 궤적 그림은 원천 모델이며 구장·시즌 차이를 표시한다.

## 구현 순서

1. [x] `persistence/pitch-sequence-repository.ts`에 전체 타석 순서와 필요한 중간 이벤트를 읽는 조회 추가.
2. [x] `game-core/pitch-sequence.ts`에 쌍 eligibility와 공통 면 교차 계산 추가. 기존 교차 계산과
       같은 의미인 작은 수학 함수만 공유하고 현재 규칙을 다시 구현하지 않는다.
3. [x] `contracts/pitch-sequence.ts`, `/api/v2/analysis/pitch-sequences/:pitcherId` 추가.
4. [x] 배합 표 → 선택 쌍의 궤적·투구 근거 순서의 화면 구현. 임의 3구 이상 패턴 탐색은 후속으로 미룸.

## 검증과 완료 조건

타석 경계, 선수 교체, 중간 tracking 누락, 자동 판정, 원천 ID 반복, 구종 필터가 중간 공을 제거하는
사례를 고정한다. 동일 궤적 간 거리는 0, 두 공 순서를 바꾸면 시간/구속 차이의 부호만 바뀌고
공간 거리는 유지되어야 한다. 비교면 전진 교차 실패는 null이며 외삽으로 조용히 대체하지 않는다.
모든 쌍을 두 실제 투구로 역추적할 수 있고 성과 표의 분모가 맞으면 완료한다.
