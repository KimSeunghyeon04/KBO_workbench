# A12. 투수 운용

선행 조건: A01·A02. 구질 변화 연결은 A05 이후다. 의료적 위험도나 최적 교체 시점은 예측하지 않는다.

## 첫 지표

| 지표               | 정의                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| 휴식일             | 경기일 − 확인된 직전 등판일 − 1; 하루 간격 연투는 0                          |
| 최근 3/7일 투구 수 | 대상 경기일 이전 3/7일의 actual 투구 합; 당일 제외                           |
| 같은 날 앞선 등판  | 경기 순서가 확인될 때만 별도 제공; 일 단위 합계와 구분                       |
| 연투 일수          | 확인된 연속 달력 날짜의 등판 수; 미수집 가능일을 임의 휴식으로 처리하지 않음 |
| 승계주자           | 투수 등장 시 before 상태의 기존 주자와 이후 typed 책임·득점 기록             |
| 반복 대면          | 같은 경기에서 해당 투수가 동일 타자를 대면한 회차                            |

반복 대면 회차를 실제 타순 1/2/3회 순환과 동일하다고 부르지 않는다. 대타나 타순 변경이 있으면
둘은 달라질 수 있다. 타순 순환 지표는 별도 roster/order 정의가 검증된 뒤에만 추가한다.
볼넷 도중 교체 등은 공식 BF 책임과 실제 대면을 구분하고, 기본 대면은 해당 투수가 실제 투구를
한 PA당 한 번으로 센다. 투구 없는 대면/교체는 별도 기록이다.

## 관측 공백

선택 기간 시작 전 필요한 7일과 직전 등판을 추가로 읽는다. 직전 기록이 없으면 휴식일 미상이며
‘충분히 쉼’으로 채우지 않는다. 공식 일정 대조로 팀 경기 누락 여부를 확인할 수 없으면 ‘수집 기록
기준 누적 투구’로 표시한다. 데이터가 없는 경기를 휴식으로 간주하는 연투 경보는 만들지 않는다.
이적 전후에도 확정된 선수 identity가 같으면 이어 읽고 미확정이면 합치지 않는다.

## 구현 순서

1. [x] `contracts/pitcher-workload.ts`, `persistence/pitcher-workload-repository.ts`에 경기별 등판과
       lookback 조회·일정 coverage·시간 순서 신뢰 상태를 추가.
2. [x] `game-core/pitcher-workload.ts`에서 날짜 창·대면·승계주자 연결을 순수 계산.
3. [x] `/api/v2/analysis/pitcher-workload/:pitcherId`와 등판 달력/표 제공.
4. [x] 경기 내 투구 구간과 A05의 구종별 구질 요약을 연결. 선발/구원, 구종·타석·시즌 차이를 함께 표시.
5. [x] 같은 조건의 성과 비교를 별도 API·접이식 패널로 제공한다. 아래 정의를 따르며 raw 차이를
       운용의 인과 효과로 해석하지 않는다. 전체 선수·시즌 검증은 [회귀 점검 기록](../2026-09-21-full-audit.md)을 따른다.

## 검증과 완료 조건

더블헤더, 순서 미상, 시즌 첫 기록, 이적, 경기 누락, 연속 3일 등판, 투구 없이 교체된 선수,
타석 중 교체와 책임 주자 승계를 검증한다. 대상일 이후 행을 추가해도 과거 workload가 변하지
않아야 하고, 다른 선수의 같은 이름을 합치지 않아야 한다. 수집 범위의 한계를 표시하면 완료한다.

등록 선발/구원은 같은 경기 로스터에서 유일한 starter/P 선수를 확인할 때만 구분하고,
불명확하면 미상으로 남긴다. 구간 표는 구종·타석 좌우로 나누며 트래킹이 없는 타석은 미상이다.
구간별 raw 구속/반응과 날짜까지의 보정 구질 변화(A05 링크)는 정의를 구분한다.

## 같은 조건의 성과 비교 — 정의 1

추가 자료나 예측 모델 학습은 필요하지 않다. 선택한 투수·시즌·경기 종류·기간 안에서만 비교하고,
휴식·누적 투구를 위한 이전 기록은 기존과 같이 시즌·팀·경기 종류를 넘어 읽는다.
`GET /api/v2/analysis/pitcher-workload/:pitcherId/comparison`은 기존 조회와 같은 strict scope를 받는다.
기존 등판 API 응답은 유지하며 화면에서 패널을 펼칠 때만 비교를 요청한다.

| 비교 항목              | 기준     | 비교 집단                   |
| ---------------------- | -------- | --------------------------- |
| 관측 휴식일            | 2일 이상 | 0일, 1일                    |
| 이전 3일 투구          | 0–29구   | 30–59구, 60구 이상          |
| 이전 7일 투구          | 0–29구   | 30–59구, 60구 이상          |
| 경기 내 실제 투구 순번 | 1–25구   | 26–50구, 51–75구, 76구 이상 |
| 같은 타자 실제 대면    | 1회      | 2회, 3회 이상               |

구속은 유효 구속 투구, 스윙률은 실제 투구, 헛스윙률은 스윙을 각각 분모로 쓴다. 등판 역할,
구종, 타석 좌우, 볼·스트라이크가 같은 셀만 짝지으며 각 셀의 양쪽 분모가 5 이상이어야 한다.
두 집단 평균을 동일한 `min(기준 분모, 비교 분모)` 가중치로 표준화하고 **비교 − 기준**을 반환한다.
지표마다 분모가 달라 공통 셀·표본도 달라진다. 원 집계 역시 비교 조건을 확인할 수 있는 표본만 쓴다.

등판 역할은 확인된 등록 선발/구원을 우선한다. 등록 정보가 없으면 같은 경기·수비 half의 최초
실제 투구 선수 ID를 확인해 `first_pitcher`/`later_pitcher`라는 **관측 역할**로 구분한다. 등록 역할과
관측 역할은 서로 다른 셀이며, 최초 실제 투구의 선수 ID가 없으면 미상이다. 자동 판정은 최초 실제
투구로 세지 않는다. 공식 선발을 추정하거나 기존 등판 API의 역할을 덮어쓰지 않는다.
`roleEvidence`에 등록/관측/미상 근거별 투구 수를 보존한다. 실제 자료의 로스터 starter/P 값이
불충분한 경우에도 관측 범위를 명확히 한 비교가 가능하다.

공통 셀의 합계가 집단별 50개·5경기 이상일 때만 조건 맞춤 값을 제공한다. 선택한 공통 셀과
가중치는 고정하고 전체 경기를 두 집단에서 함께 600회 복원 추출해 차이의 2.5/97.5 백분위수를
구한다. 재표집에서 어느 공통 셀의 한쪽 분모라도 0이면 그 반복은 제외한다. 유효 반복이 480회
미만이면 `unstable_interval`로 수치를 보류한다. 그 밖의 표본 부족은 `insufficient_support`다.
입력·경기·셀 정렬과 난수 seed를 고정하므로 같은 입력의 결과는 동일하다. 이 구간은 개별 비교용이며
여러 항목의 동시 검정이나 통계적 유의성 순위를 제공하지 않는다.

역할·구종·타석 좌우 미상은 조건 제외로 센다. 직전 관측 등판이 없거나 같은 날 복수 등판이면
휴식·최근 투구량 비교에서 추가 제외한다. 이 경기의 투구 순번·대면 비교는 유지한다. PA/타자 연결이
없으면 대면 비교만 제외한다. 실제 투구 순번과 대면은 조건 필터 전에 계산해 tracking 누락으로
앞당겨지지 않는다. `전체 = 조건 제외 + 운용 조건 제외 + 분류 가능`을 항목별로 검증한다.

구속은 원 관측값이며 구장 속도 보정은 하지 않는다. 실제 코스, 상대 타자 능력, 구장, 시즌 내 시기와
다른 운용 변수까지 통제한 결과가 아니다. 장기 등판을 유지한 투수의 선택 효과와 수집 공백도 남아
피로·부상 위험 또는 교체의 인과 효과로 해석하지 않는다. 빈 집단과 미상은 0으로 대체하지 않는다.

## 모듈과 비용

- `workload-context`는 기존/신규 repository가 실제로 공유하는 current 경기 선택과 등판 이력만 맡는다.
- `workload-calendar`는 날짜별 합계를 한 번 만들고 직전 등판·최대 7일 창을 계산한다.
  기존 등판 응답·sourceHash·더블헤더 정의를 유지한다.
- 신규 repository는 대상 투수의 narrow pitch fact와 단일 tracking 연결에서 셀을 먼저 집계한다.
  대면 회차의 작은 결과를 한 번 materialize해 투구마다 window를 재실행하지 않는다.
  전체 시즌 wide trajectory view, 원장 재컴파일, 모델 재학습을 사용하지 않는다.
- 비교와 경기 bootstrap은 DB 연결 반환 뒤 기존 분석 worker 1개/대기 16개의 풀에서 실행한다.
  별도 서비스·범용 비교 registry·영속 예측 행·DB migration을 추가하지 않는다.
- 브라우저는 항목·지표 전환 시 이미 검증한 응답을 표시한다. 지표를 다시 계산하지 않는다.
