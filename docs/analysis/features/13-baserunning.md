# A13. 주루와 작전 결과

선행 조건: A01·A02. 득점가치는 A11 이후. 주력·수비 위치나 주루 판단의 인과 효과는 추정하지 않는다.

## 1단계: 관측된 결과

도루·도루실패·견제사와 1루→3루, 2루→홈 등의 추가 진루를 집계한다.
도루 성공률은 SB/(SB+CS)이며 견제사를 자동으로 CS에 포함하지 않고 compiler reason을 따른다.
기존 `baserunner_game_facts`의 counts를 재사용한다. 개별 기회 분석은 play·movement를 읽는다.

추가 진루의 첫 기회는 ‘완료된 단타 플레이 시작에 1루 또는 2루에 있던 주자’처럼 명시적으로
정의한다. 병살·FC·오류/간섭 등 복합 결과는 별도 제외 사유로 둔다. 이미 귀속이 불분명한 주자 이동을
플레이 결과에서 다시 추론하지 않는다.

before의 주자를 기준으로 후보를 열고 after와 typed movement를 함께 확인한다. 이동 행이 없는
잔류 주자도 기회 분모에 들어간다. 동일 주자가 한 atomic play에서 여러 단계 이동한 경우 하나의
최종 관측 결과로 집계한다. 단일 movement 행을 기회 하나로 취급하지 않는다.
수비 위치·타구속도·주력은 없으므로 이 비율은 상황을 완전히 조정한 주루 능력 점수가 아니다.

## 2단계: 플레이 가치와 작전

A11의 공격팀 관점 플레이 득점가치를 도루·번트 등 관측된 play에 연결한다.
순수 도루 플레이처럼 행동이 하나인 경우와 타격+진루가 함께 있는 플레이를 구분한다.
복합 플레이의 RE 변화 전체를 개별 주자의 공로로 배분하지 않는다.
번트는 `is_bunt` 등 명시된 기록만 분류하고 실패한 작전 의도를 원문이나 결과에서 지어내지 않는다.
번트 전후 가치와 비번트 관측 결과를 비교해도 ‘번트를 하지 않았을 때’의 인과 반사실은 아니다.

## 구현 순서

1. [x] `contracts/baserunning-analysis.ts`, `persistence/baserunning-analysis-repository.ts`에
       game summary와 구체적인 기회 조회를 분리해 추가.
2. [x] `game-core/baserunning-analysis.ts`에 같은 runner/play의 관측 결과 요약 추가.
       compiler movement validation을 다시 작성하지 않는다.
3. [x] `/api/v2/analysis/baserunning/:playerId` 및 선수·팀 비교 표와 근거 play 연결.
4. [x] A11 이후 가치와 미지원/복합 플레이 상태를 별도 계약으로 추가.

## 검증과 완료 조건

잔류로 이동 행이 없는 주자, 한 play의 다단계 진루, 더블스틸, 견제사, 대주자, 득점 취소,
추가 진루 아웃, 복합 실책 플레이를 포함한다. 실제 주자 identity를 유지하고 대주자에게 이전
주자의 시도를 귀속하지 않는다. 모든 eligible 기회가 성공·잔류·아웃·해석 불가 중 하나로 분할되고,
동일 play의 가치가 중복 합산되지 않으면 완료한다.
