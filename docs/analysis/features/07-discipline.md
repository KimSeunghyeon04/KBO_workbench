# A07. 타자 선구안 확장

선행 조건: A01. 기존 [타자 선구안 계산](../../batter-discipline-analysis.md)을 유지한다.

## 제공할 결과

기존 실제 코스와 포심 가정 비교에 경기 종류·기간 필터와 두 기간 비교를 추가한다.
Zone/Swing/Z-Swing/Chase 및 헛스윙을 분모와 함께 표시한다. 새 종합 선구안 점수는 만들지 않는다.

## 유지할 계약

- 번트 PA·고의사구 PA·사구 투구·번트 파울 등 기존 상황 제외 규칙을 유지한다.
- conventional, 궤적 지도, 포심 비교 가능한 common, 동일 조건 비교 가능한 paired 표본을 합치지 않는다.
- source-plane의 실제 코스와 신장 존을 사용한다. 중간면 구질 보정은 적용하지 않는다.
- 비교군은 같은 시즌·경기 종류의 다른 타자다. 날짜 필터를 대상에만 적용하는 첫 버전에서는 기준군이
  시즌 전체라는 사실을 표시한다. 기간별 리그 변화 비교는 기준군도 같은 기간으로 고정한 별도 모드로 제공한다.
- 같은 카운트·구종·stance·5km/h 구간·코스 등 기존 조건과 타자 제외, 비교군 최소 20구를 유지한다.
  두 비교의 차이를 계산할 때는 두 쪽 모두 비교 가능한 동일 대상 투구만 사용한다.
- 2024 이전 신장 존은 당시 심판 존을 복원한 것이 아니다. 루킹 판정 오류율이나 ABS 정확도 평가로 바꾸지 않는다.

## 구현 순서

1. [x] 기존 `contracts/batter-discipline.ts`에 대상 기간·기준 범위·경기 종류를 명시적으로 추가.
2. [x] 기존 `persistence/batter-discipline-repository.ts`에서 범위 manifest와 확정 키를 같은 snapshot으로 조회.
       sourceHash에 적용 분류 자료를 포함하고 source-plane reference 키도 scope와 연결.
3. [x] `game-core/batter-discipline.ts`에 기준/대상 필터 순서를 명시. A04와 실제로 같은 코스 함수만 추출.
4. [x] 기존 service/worker의 단일 시즌 준비와 요청 공유를 유지하면서 범위별 메모리 상한 점검.
5. [x] 기존 페이지에 기간 비교·비교 표본 설명 추가. 각 표의 표본이 달라질 때 숫자만 나란히 놓지 않고
       전체·공통·paired 수를 명확히 표시.

API는 기존 `/api/v2/analysis/batter-discipline`와 `/:batterId`를 확장한다.
없는 키·기준·비교군을 평균값으로 채우는 fallback은 추가하지 않는다.

## 검증과 완료 조건

현재 `tests/game-core/batter-discipline.test.ts`의 paired 분모 보존·자기 타자 제외·미상 층화·
신장/제공자 존 독립성을 그대로 통과시킨다. 추가로 기간 경계, 경기 종류, 작은 비교군, 기준군 범위
변경에 따른 기대값·hash 변경, 빠른 타자/기간 전환의 응답 역전을 검증한다.
같은 기존 입력·정의에서 결과가 같고 추가 필터의 영향만 재현되면 완료한다.
