# 11회 승리확률과 분석 조회 개선

기존 운영 점검에서 확인한 2025 승리확률 미지원과 매치업·투수 변화·데이터 품질의 조회 지연을
개선했다. 원장과 sealed 경기 fact, 원래 최종 승패는 변경하지 않는다.

## 11회 기준 학습

2022–2024 정상 종료 경기를 적용 연도의 연장 상한으로 재구성한다. 9–11회에 끝난 결과는 유지하고,
12회에 진입한 경기는 관측된 11회말 3아웃 동점에서 학습용 무승부로 종료한다. 이후 상태와 원래
최종 승패를 학습 입력에서 제외한다. 종료 증거가 없거나 콜드·몰수·불완전한 경기는 제외한다.
관측되지 않은 이닝을 추가하는 변환은 지원하지 않는다. 원본 경기 규정과 기록은 보존한다.

훈련·2023/2024 후보 비교 모두 같은 11회 조건을 사용했다. 표본을 자른 뒤 경기별 고유 상태와
가중치 합계 1을 다시 계산한다. 2025 실제 결과는 전처리·후보 선택에 사용하지 않는다.

| 항목                                |                 결과 |
| ----------------------------------- | -------------------: |
| 훈련 경기 / 상태                    |      2,140 / 173,816 |
| 채택                                | 다항 로지스틱, λ=0.1 |
| 2023 log loss, 상태표 → 채택 모형   |      0.6434 → 0.5925 |
| 2024 log loss, 상태표 → 채택 모형   |      0.5706 → 0.5493 |
| 게임 bootstrap 차이 95% 구간        |  −0.04027 ~ −0.03154 |
| 2025 평가 경기 / 상태 / 미지원 상태 |     710 / 57,431 / 0 |
| 2025 log loss / Brier               |      0.5862 / 0.3554 |

2025 정규시즌 수집 720경기 전체를 지원한다고 해석하지 않는다. 정상 종료·종료 상태 검증을
통과한 710경기가 평가 대상이다. 당시 12회를 고려한 선수 운용 차이가 남을 수 있어 화면에도
설명한다. 이전 모델 정책을 조용히 재사용하지 않도록 새 정책을 strict 계약에 고정했다.
기존 모델 파일은 보존하고 재학습한 모델의 포인터만 기존 원자적 저장 절차로 공개한다.

## 조회 경로

- 매치업: 비교 조건에 필요한 투구 fact·canonical tracking link·PA eligibility만 읽는다. 경기별로
  조인 범위를 제한해 20만 투구 각각의 반복 인덱스 탐색을 줄였다. 타자 코스 조회도 경기 범위를
  먼저 제한한다. 직접/유사/타자 제외 리그 집계와 응답 전체 hash는 수정 전후 동일하다.
- 투수 변화: 보정과 포심 기준 파일을 먼저 확인한 뒤 준비되어 있으면 대상 투수만 읽는다.
  완료 경기 전용 기준은 별도 해시로 구분한다. 원천 해시를 제외한 응답 전체가 운영의 기존
  결과와 동일하다. 결과 캐시가 비어 있는 재시작 후에도 시즌 전체 투구를 다시 읽지 않는다.
- 데이터 품질: 비싼 집계 전에 같은 snapshot의 current revision·분류·유효 신장으로 캐시 키를
  확인한다. 신장 보충도 캐시를 무효화한다. 캐시가 없을 때만 투구/PA를 경기별로 집계하고
  동일한 물리 계산으로 궤적 eligibility를 확인한다. 응답 전체 hash는 수정 전후 동일하다.
- 빌드·통합 테스트: 저장된 연구/배포 자료와 복구용 archive가 Docker context와 테스트 복사에
  포함되지 않게 했다. 실제 테스트 fixture와 소스는 유지한다.

동일 검증 DB 사본의 2025 표본을 3회 조회했다. 아래 첫 조회는 보정·기준 파일이 준비된 상태에서
프로세스 결과 캐시가 비어 있는 경우다. HTTP·렌더링을 제외했고 OS/DB cache는 비우지 않았다.

| 조회        | 개선 전 첫 조회 | 개선 후 첫 조회 | 개선 후 다음 2회 |
| ----------- | --------------: | --------------: | ---------------: |
| 매치업      |         8,930ms |         1,129ms |      993–1,018ms |
| 투수 변화   |         8,137ms |           156ms |          12–16ms |
| 데이터 품질 |        13,491ms |         4,029ms |        139–148ms |

소수 표본의 관측 범위이며 p95나 부하 상한이 아니다. 보정 파일도 없는 최초 생성은 별도 비용이다.
데이터 품질의 최초 시즌 전체 계산과 구종 기대 효과의 약 1초 이상 응답은 남은 개선 대상이다.

## 검증과 운영

12회 결과 변경 불변성, 원본 불변성, 종료 증거 부족, 9–11회 승패, 연장 상한 확대 거부,
미래 시즌 label 변경 불변성, 실제 2025 승리확률 곡선 표시를 회귀 테스트에 추가했다.
DB 테스트는 신장 보충과 current revision 변경의 캐시 무효화, 저장된 기준 재사용과 계산 전
DB 연결 반환을 확인한다. 실제 2025년 9·10·11회 승패와 11회 무승부 7경기에서 확률·WPA 합계를 확인했다.

원 측정·모델·검증 로그는 `analysis/deployment/20260920-improvements/`에 보존한다.

lint·format·typecheck·schema check·build와 기본 테스트 831개가 통과했다. 별도의 격리 DB에서
통합 테스트 70개를 실행했고, 격리 Compose E2E의 import·replay·교정·분석 화면·재시작·
backup/restore 검증도 통과했다. 컴파일 평균 5.361ms / p95 7.785ms,
재생 구성 평균 1.138ms / p95 1.744ms로 기존 성능 기준을 유지했다.

2026-09-20 운영 API/web과 모델을 교체했다. 추가 DB migration은 없다. 검증 사본의 모델과
운영 원천 manifest가 일치하는 것을 확인한 뒤 writer를 정지하고 기존 workspace lock과
원자적 저장 경로로 모델을 공개했다. 이전 모델 파일·포인터 사본과 이전 이미지 태그를 보존했다.
모델 hash는 `255f7114a524edbba8690b4d3878e792ae6d5a0d1ca9a22f998af21f8db21656`이다.

운영 HTTP 검사 29건이 통과했다. 9·10·11회 승패 및 11회 무승부 7경기의 모델 준비 상태와
종료 가치·WPA 보존을 확인했다. 매치업·품질 응답의 전체 hash, 투수 변화의 새 원천 해시를
포함한 전체 응답을 검증 사본과 대조했다. RE24·카운트 가치·투수 코스·타자 성향도 정상 응답했다.

| 운영 HTTP 조회 | 재시작 후 첫 조회 | 이후 4회 범위 |
| -------------- | ----------------: | ------------: |
| 매치업         |           1,279ms | 1,011–1,090ms |
| 투수 변화      |             699ms |       18–22ms |
| 데이터 품질    |           4,070ms |     132–137ms |

보정·기준 파일을 준비한 상태의 순차 HTTP 왕복이다. DB/OS cache는 비우지 않았고
소수 표본이므로 p95나 동시 사용자 부하 상한을 의미하지 않는다. 승리확률 7경기는 279–417ms였다.

운영 브라우저에서 2025-03-30 KT–롯데의 650개 replay frame을 검증해 불러오고 승리확률
패널을 펼쳤다. 11회 재구성 안내, 실제 홈 승리확률 곡선, 종료 가치 0.500과 보존 일치를
확인했다. 규정 미지원 안내와 브라우저 console warning/error는 없었다.

4,693개 sealed revision의 document/projection hash와 기존 current/active 파일 11개는
배포 전후 동일했다. 운영 원장과 최종 경기 결과는 보존했다.
