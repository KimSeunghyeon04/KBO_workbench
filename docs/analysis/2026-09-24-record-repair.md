# 2020–2025 기록 오류 교정과 수집 검증 강화

2026-09-24 전체 선수 공개 기록 대조에서 확인한 오류를 원장 교정과 새 sealed revision으로
106경기에 반영했다. 사전 조사와 교정 후 검증은 구분하며, 이전 조사 결과는
[전체 선수 기록 대조](2026-09-24-all-player-records-audit.md)에 보존한다.

## 교정 근거와 범위

| 구분      | 범위                          | 교정 근거                                                            |
| --------- | ----------------------------- | -------------------------------------------------------------------- |
| 장타 종류 | 3경기·3타석                   | 보존된 이닝별 기록지와 KBO 선수 일자별 기록의 일치                   |
| 타점      | 102경기·103개 선수 경기       | 경기 타점 잔차와 유일한 미판정 득점 타석, 또는 타석별 누적 타점 관측 |
| 투수 ID   | 2021-03-30 두산–삼성 시범경기 | 원천 기록지와 KBO 공식 일자별 투수 기록의 ID 60146                   |

장타 교정은 다음과 같다.

| 경기               | 선수   | 타석 결과     | 해당 시즌 장타율 |
| ------------------ | ------ | ------------- | ---------------- |
| 2020-05-13 KT–NC   | 박민우 | 3루타 → 2루타 | .478 → .475      |
| 2022-06-30 KT–삼성 | 황재균 | 단타 → 2루타  | .378 → .380      |

박민우의 최종 3루 도달, 김도영의 태그아웃을 보존한다. 황재균은 다음 볼넷까지 1루로 표시된
관측 7개를 2루로 교정하고 기존 이동 행을 2루 잔류로 맞춘다. 이후 주자 상태는 원래와 같다.
안타 종류만 바꾸고 주루 상태를 방치하지 않는다. 점수·아웃·타석·실투구 수는 모두 보존한다.

타점은 실책 출루 102건과 희생플라이 1건이다. 여러 주자가 득점하더라도 경기 기록으로 확인한
1타점만 명시한다. 희생플라이 사례는 앞선 교정으로 득점 주자 이동이 이미 추가됐으나 타점 판정이
빠져 있던 2024-05-04 김현수 타석이다. 불특정 득점 타석에 시즌 부족분을 임의 배분하지 않는다.

처음 확인한 정규시즌 88건 외에 전체 경기 검증에서 시범 11건, 포스트시즌 3건, 연습경기 1건을
추가 확인했다. 데이비슨(2024-03-19)과 유한준(2020-05-01)은 미판정 득점 타석이 둘이었다.
각 타석의 원천 `batterRecord` AB/H/HR 누적값을 실제 완료 타석과 맞춰 관측 시점을 확인하고,
RBI가 1 증가한 타석만 교정했다. 다른 후보의 RBI 증가량은 0이었다.
연습경기는 대응 KBO 공개 시즌 범위가 없으므로 보존 경기기록과 타석별 관측을 근거로 삼았다.

투수는 이름이 같은 두 선수를 합치지 않는다. 2021-03-30 경기의 17개 명시적 이벤트 참조만
51454에서 60146으로 바꾸며 두 선수의 로스터와 원문은 유지한다. 해당 구간 4타자·1이닝·9구·
2피안타·1실점과 연결된 tracking 9개의 원시 관측값 및 연결 identity를 보존한다.

## 수집 시 검증

`collection`의 공식 기록 매핑이 선수 ID가 있는 이닝별 기록지 약호를 해석한다. 모든 타격 결과를
분류할 수 있고 명시적 안타·홈런 합계와 일치할 때만 선택적 공식 2루타·3루타를 보완한다.
원천이 없는 선택 필드를 0으로 채우지 않는다. 기존 명시적 2루타·3루타와 충돌하면 기존 값을
보존하고 source warning을 남긴다. 이름으로만 나열된 `etcRecords`는 선수 ID 대신 사용하지 않는다.

중계와 확정된 공식 장타가 다르면 compiler의 `official_batter_record_mismatch`가 import를
차단한다. 미해석·불완전 기록은 endpoint·행 위치·원문이 있는
`source.official_batter.hit_breakdown_unverifiable` 경고로 남겨 검토할 수 있게 한다.
중계 결과를 자동 교체하지 않는다.

4,698경기(봉인 4,697경기와 검토 중 1경기)의 보존 record를 SHA-256 검증 후 전수 검사했다.
121,976개 타자 행 중 실제 이닝 기록이 있는 108,922행의 108,787행(99.876%)을 보완할 수 있었다.
타석 기록이 비어 있고 명시적 H/HR이 모두 0인 13,054행은 보완이나 경고 없이 생략한다.
빈 `/` 슬롯처럼 해석을 확정하지 못하는 135행은 경고로 유지한다. 전체적으로 mapper 오류와
원문 hash 불일치는 없었다. 수비 위치를 거쳐 흐른 타구 등의 추가 약호는 실제 record와 같은 이닝
relay를 교차 확인하고 비식별 테스트로 고정했다.

compiler는 공식 기록에 양수 실적이 있지만 해당 선수 ID의 계산 행이 없을 때
`official_batter_record_missing` 또는 `official_pitcher_record_missing`을 차단 finding으로 남긴다.
0뿐인 행과 compiler가 계산하지 않는 자책점만 있는 행은 이 조건으로 차단하지 않는다.
미판정 타점은 기존 `official_rbi_not_verifiable` 경고로 남긴다. 이 검증은 collection 후,
correction 후, import 전의 공통 compiler 경로에서 실행된다.

## 운영 반영과 재현 자료

DB와 파일 workspace를 한 쌍으로 백업하고 SHA-256을 확인한 뒤, DB draft 생성 → version을 가진
structured correction batch → 전체 compile → commit → import job 순서로 처리한다.
기존 sealed fact를 갱신하거나 original/source를 덮어쓰지 않는다.

원본 교정 대상 문서, 명령, 메모리 검증, 적용 결과와 새 revision hash는
`analysis/deployment/20260924-record-repair/`에 보관한다. `prepare-rbi.mjs`와
`prepare-extra-base-and-identity.mjs`는 운영 쓰기 없이 교정안을 재현한다.
`apply-plans.mjs`는 사전 검토 문서 hash와 서버 응답 hash가 일치해야 다음 단계로 진행한다.

백업: `.backups/kbo-workbench-20260924T081959121Z/`.

## 교정 후 검증

- 총 4,697경기 중 106경기의 revision만 1씩 증가했다. 나머지 4,591경기의 revision과 문서 hash는
  처음 snapshot과 일치한다. 교정한 경기의 source bundle hash는 모두 보존됐다.
- 106경기를 봉인된 typed fact에서 다시 읽어 교정 계획과 문서 전체를 대조했다. 일치했고
  최신 compiler의 blocking finding은 0이었다. 135개 structured command를 사용했다.
- 보존 공식 경기 타점과 계산 타점의 차이는 전체 경기에서 0건이다. KBO 공개 기록과 비교한
  정규시즌 1,750개, 시범·포스트시즌 1,520개 타자·시즌의 RBI도 모두 일치한다.
  계산 행이 없는 공식 행 633개는 공식 RBI가 모두 0임을 별도 확인했다.
- 정규시즌 53,998개 기본 지표와 시범·포스트시즌 30,290개 지표를 운영 API로 다시 대조했다.
  장타 종류·총루타·SLG·OPS의 실제 차이와 투수 ID에서 생긴 차이가 해소됐다.
  정규시즌 AVG·OBP·SLG는 분모가 유효한 모든 비교에서 일치한다.
- 경기별로는 원문을 확정할 수 있는 108,757개 타자 경기의 217,514개 2B/3B를 대조했다.
  알려진 교정 3건 외의 오류와 시즌 합계에서 상쇄되는 추가 오류는 없었다. 비교 시점에 미반영된
  김도영 1행도 revision 2와 검토 hash로 일치를 확인했다. 빈 슬롯 때문에 자동 비교에서 제외한
  장타 양수 11행은 표시된 장타와 명시적 H1이 현재 계산값과 일치함을 별도로 확인했다.
- 공식 타자 121,946행·투수 45,423행에 새 missing-record 규칙을 전수 적용한 읽기 전용 SQL에서도
  잔여 위반은 0건이었다. 계산 행이 없는 타자 11,753행·투수 8행은 비교 대상 계수가 모두 0이었다.
- 운영에는 이번 collection 3개 모듈과 compiler 1개 모듈만 기존 이미지에 반영했다. 배포된
  소스·JS 8개 파일의 SHA-256을 검증했고, 실제 운영 compiler에서 이전 ID 오류는 차단,
  교정 문서는 통과함을 확인했다. 별도 작업의 workspace 리팩터나 migration은 배포하지 않았다.

`lint`, `format:check`, `typecheck`, `schema:game:check`, `build`가 통과했다.
전체 unit/API/UI·architecture 테스트 1,179개와 격리 PostgreSQL 통합 테스트 76개가 통과했다.
558행 경기 compiler 성능은 평균 4.081ms, p95 5.099ms로 기준 이내였다.

핵심 결과는 `verification.json`, `comparison-regular.json`, `comparison-extended.json`,
`extra-base-game-comparison.json`, `extra-base-kim-repair-confirmation.json`,
`missing-records-current-audit.json`, `deployed-verification.json`에 보관한다.

출전 경기수 정의, OPS 표시 반올림, 원천 자책점 미제공은 이번에 근거가 확정된 이벤트 오류와
구분한다. 누락 자책점을 0으로 채우거나 출전수를 맞추기 위한 가짜 타석·투구를 추가하지 않는다.
G 정의 차이는 정규시즌 1,240개·시범/포스트시즌 358개 비교에 남아 있다. OPS 356개는
OBP/SLG를 각각 표시 자리로 반올림한 뒤 더하는 KBO 방식과의 차이다. 정규시즌 77개 투수·시즌은
일부 경기의 원천 자책점이 없어 ER/ERA의 완전 비교가 불가능한 상태를 유지한다.
