# 선수 분석의 A/B 기간 비교

기본 기록, 구질·움직임, 타자 반응·성적, 선구안, 코스·결정구는 같은 A/B 시즌·날짜 선택기를
사용한다. 각 날짜를 비우면 그 시즌 전체이며 날짜는 해당 시즌 안의 실제 날짜여야 한다.
시즌 변경은 그 쪽 날짜만 지운다. 두 기간은 겹칠 수 있고 같은 기간도 비교할 수 있다.
구질과 선구안은 공통 분석 시즌 범위인 1982–2200을 사용한다. A/B 선택과 URL 복원에는 같은
시즌 검증이 적용된다. 선구안은 경기 시즌에 적용할 수 있는 가장 최근의 스트라이크존 기준을 사용한다.

선택기를 펼치거나 날짜를 편집하는 동안에는 추가 조회하지 않는다. `두 기간 비교 적용`은
URL을 먼저 확정한 뒤 한 비교 요청을 보낸다. 편집 중에는 기존 결과를 숨긴다. 명시적으로 비운
날짜도 `periodAFrom`, `periodATo`, `periodBFrom`, `periodBTo`의 빈 문자열로 유지해 기본 조회
기간을 다시 상속하지 않는다. `periodCompare`, `periodASeason`, `periodBSeason`과 함께 브라우저
뒤로 가기와 선수 분석 탭 이동에서 복원한다. 상황 필터는 각 분석의 지원 범위를 따른다.
투수 코스·결정구와 타자 반응·성적의 기간 비교 탭은 선수 목록과 시즌 선택지를 유지하며,
분석 결과는 적용된 두 기간의 비교 요청으로 가져온다.

## 계산과 표본

- 기본 기록: 팀별 typed 성적의 분자·분모를 서버에서 합산해 기존 `battingStatistics`와
  `pitchingStatistics`로 계산한다. 이적 전후 비율의 단순 평균을 사용하지 않는다. ERA 미확정과
  ER 확인 경기 ERA를 구분하고 확인된 경기 수·이닝을 유지한다. 상황별 투구 필터는 적용하지 않는다.
- 구질: 기존 repository의 기간 프로필을 사용하고 비교 때문에 GMM을 추가 실행하지 않는다.
  원 중계 구종별 사용률·구속·보정 가로/세로·도착 시간·Whiff%를 비교한다. 사용률은 전체 실제
  투구, 구속은 유효 구속, 보정 좌표는 보정 완료 표본이 분모다. 시즌 간 상대 좌표·도착 시간은
  각 시즌 값을 나란히 보여 주되 차이는 미제공한다. 동일 시즌도 reference hash가 다르면 차감하지 않는다.
- 타자 특성: 전체·구종·구속대·코스의 반응과 종결 구종별 PA/AVG/SLG를 분리한다. 한 PA 결과를
  여러 투구에 복제하지 않는다. 코스는 포수 시점이며 행은 위에서, 열은 왼쪽에서 센다.
- 선구안: conventional 관측 Zone/Swing/Z-Swing/Chase와 지도 표본 Whiff를 서로 다른 분모로
  표시한다. 지도·포심 공통·리그 비교 표본 수를 유지한다. 리그 비교 기간 정책은 공통 필터로 유지한다.
- 코스·결정구: 기존 두 지도와 같은 선택기에 전체 Whiff/CSW/PutAway 등 반응 비교를 함께 제공한다.
  이전 시즌 고정 표는 이 A/B 비교로 통합한다. 지도 색상은 공통 눈금을 유지한다.
- 투수 변화: 같은 A/B 선택기로 자유 기간의 구질 프로필을 조회한다. 종료일까지 완료된 최근 3등판과
  이전 5등판의 자동 비교·경기 단위 재표집 구간은 별도로 유지한다. 자유 기간 프로필의 시즌 전체
  기준과 자동 비교의 완료 경기·종료일 기준을 혼동하지 않도록 화면에 명시한다.

차이는 B−A이며 비율 차이는 %p, 구속은 km/h, 좌표는 cm, 시간은 ms다. 이닝은 아웃에서 표시하고
이닝 차이는 아웃 수로 보여 준다. 분모 0·미확인 평균은 null이며 관측 0과 구별한다. 차트는 같은
지표의 공통 축을 사용하고 정확한 값과 분자·분모를 표에서 제공한다. 인과 효과·의학적 진단·기량
변화의 확정을 제공하지 않는다.

## API와 원천 일관성

기본 기록 `/api/v2/analysis/statistics/:playerId/comparison`, 구질
`/api/v2/analysis/pitch-shape/:pitcherId/comparison`, 타자 특성
`/api/v2/analysis/batter-profile/:batterId/comparison`, 선구안
`/api/v2/analysis/batter-discipline/:batterId/comparison`은 기능별 strict query/response를 사용한다.
A는 `season/dateFrom/dateTo`, B는 `compareSeason/compareDateFrom/compareDateTo`이며 나머지는
두 기간 공통 조건이다. 비교 지표의 산식은 game-core의 명시적 함수가 소유한다. 웹은 수치를 재계산하지 않는다.

각 기존 reader는 자체 repeatable-read snapshot과 원천 hash를 유지한다. CPU·worker 실행 중
DB 연결을 잡아 두지 않으며, A → B → A 원천 hash 재검증으로 조회 사이의 기록 갱신을 거부한다.
시즌이 달라 정상적으로 다른 A/B hash를 같아야 한다고 요구하지 않는다. 코스 지도는 기존 단일
snapshot의 두 기간 조회를 유지한다. 실패는 원래 오류와 명시적 재시도로 복구한다.

서버가 적용 query·선수·scope·원천 hash·지표와 표본을 반환하고 웹은 strict decode 및 요청/응답
일치·중복 지표·차이·비율 분모를 검증한다. sealed 기록·projection·migration은 변경하지 않는다.
