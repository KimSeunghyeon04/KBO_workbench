## 실제 자료 검증

[실데이터 검증 절차](real-data-validation.md)는 운영 DB를 읽기 전용으로 복사하고 기존의
분류·학습 CLI를 순차 조립한다. 운영 화면의 갱신 작업은 별도 worker에서 같은 학습 함수를 호출하며
GET 요청이나 새 서비스로 전체 학습을 옮기지 않는다. 코드 hash가 바뀌면
명시적으로 재학습하며 이전 로그와 불변 모델은 남긴다.

- 수집 4,693경기 중 정규 4,316, 시범 256, 포스트시즌 86, 미분류 35경기다.
  2023 정규시즌은 현재 수집분에서 716경기이고 나머지 5개 시즌은 각각 720경기다.
- RE24는 pooled, 카운트 RE는 기존 shrinkage 100을 유지했다. 승리확률은 11회 기준으로 다시
  학습해 다항 로지스틱(λ=0.1)을 채택했다. 훈련 2,140경기, 2025 평가 710경기이며 미지원 상태는 0이다.
- 구장 득점·홈런 효과는 Poisson을 채택했다. 구종 기대 효과는 1,318,591구를 읽어 스윙·헛스윙·
  루킹 모두 코스 포함 모델을 채택했다. 2025 공통 지원 표본은 실제 217,849구 중 186,313구다.
- 원천 해시는 유지하면서 월별 투구 view의 확장 순서를 제한했고, 모델 검증용 신장을 6회 대신
  한 번 읽도록 바꿨다. 구장 집계는 두 번의 전체 정렬 대신 한 번의 경계 순번 집계를 사용한다.
  이닝 요약도 팀·경기 행마다 반복하지 않고 한 번 계산한 결과를 재사용한다.
  A06도 경기 범위를 먼저 고정하며 투구 쌍·장벽·응답 hash가 실데이터에서 동일함을 확인했다.
- 후보를 2023/2024로 선택하고 2025 결과로 문턱을 바꾸지 않았다. 기존 구장 보정 연구에서
  2025를 이미 살펴봤으므로 전체 체계의 완전히 미관측인 외부 검증이라고 부르지 않는다.

## 추상화와 병목 관리

- 범위·고정 SQL 조건·원천 해시·실제 코스·atomic play 읽기처럼 의미가 같은 작은 기능만 공유한다.
  PA/BF와 투구의 분모, 구질/실제 코스, 측정 편향/구장 득점 효과는 각 소유 모듈에 둔다.
- API의 궤적·모형 적용은 worker 1개/대기 16개의 공유 풀을 사용한다. 전체 학습은 별도
  maintenance CLI 또는 모델 갱신 작업의 worker 하나로 실행하며 DB snapshot 연결을 먼저 반환한다.
- 파생 파일의 hash·원자적 공개 I/O만 공유하고 모델별 schema/의미 검증은 각 workspace가 맡는다.
  새 범용 모델 registry, query DSL, 서비스 또는 DB 예측행 복제는 만들지 않았다.
- 통계는 DB에서 grain별로 먼저 집계한다. A10은 월별 SQL/5,000행 전달, 숫자 행렬 재사용,
  A14는 적합당 역행렬/경기 score 재사용으로 반복 비용을 줄였다.
- 기존 구질/선구안 cache는 신선한 원천 해시 확인 후 재사용한다. 새 모델도 경기 revision,
  분류 dataset, 사용하는 신장 등 보완자료가 바뀌면 미준비 처리한다. TTL만 믿지 않는다.
- 표·근거 목록은 페이지로 나누고 모형 패널은 열 때만 요청한다. 학습 모델이 없는 조회에서
  필요 없는 궤적 계산을 생략한다.

## 운영 반영

새 migration head는 `0012_competition_game_links`이다. sealed facts/analytics contract 4는 그대로다.
공식 일정은 시즌별 12개월 × 3종류 응답을 검증한다. collection에서 두 제공자의 경기 ID를
실제 날짜·팀 코드·더블헤더 순번으로 유일하게 연결하고 두 원본 ID를 별도로 보존한다.
취소 등 링크 없는 행은 원문에 보존하며 전체 일정 확보율로 과장하지 않는다. 일부 실패·충돌·
기존 분류 누락은 current dataset을 바꾸지 않는다.

새 화면의 기본은 확인된 정규시즌이고 기존 구질/선구안·품질은 수집 전체다. 미분류 자료를
정규시즌으로 추정하지 않는다. 모델이 준비되지 않은 상태도 정상 응답이며 기술 통계는 유지한다.
[README의 실행 명령](../../README.md#분석-기능-확장)을 사용하고, 학습의 실제 평가 보고서로
채택 여부를 판단한다. 운영 반영 전 paired backup을 만들었고, 공식 분류·파생 모델을 추가했다.
운영 원장과 4,693개 sealed revision의 document/projection hash는 배포 전후 동일하다.

모델 상태·필요 모델 갱신·취소·재시작 복구·선택적 6시간 자동 점검을 운영에 연결했다.
당시 여섯 모델은 최신이었고 원천 재확인 뒤 공개했다. 구질/매치업 실제 재학습 hash는 기존과 동일했다.
갱신 worker는 원시 투구 복제를 없앴으며 구질 학습의 관측 최대 RSS는 3.74GiB였다.
매치업 HTTP 재조회 p95는 712ms였다. 범위와 조건은 [모델 운영 검증 기록](2026-09-20-model-operations.md)에 있다.

## 2026-09-21 시즌별 학습 확장

2020–2025 적용 시즌 선택, 일반 모델의 2023–2025 학습·검증·조회, 시즌별 자동 갱신을 구현했다.
승리확률은 지원 규정 이력상 2025만 제공한다. 이력 부족은 강제 학습에서도 제외한다.
고정 연도 대신 적용 시즌의 직전 두 연도를 검증하고, 전처리와 후보 선택에는 그 이전 자료만 쓴다.
기간만 공유하고 지표별 적합·검증·파일 공개 책임을 유지했다. 카운트의 RE24 사전표를 같은 기간의
후보 사이에서 재사용하며, 전체 시즌 작업은 worker 하나로 직렬화한다.

단위/API/UI 테스트 863개, DB 통합 72개와 격리 Compose E2E가 통과했다. E2E는 2023 시즌의
5개 모델 공개와 승리확률 제외, 2025 파일 보존, 시즌 선택·미지원 UI와 재시작을 확인했다.
일반 품질 게이트도 통과했다. 운영 2023·2024 모델 10개와 세 시즌 실제 분석 응답 15개의 hash가
별도 검증 환경과 일치했다. 기존 2025 모델 6개와 원장·4,693개 sealed revision은 유지했다.
실데이터 모델과 운영 결과는 [검증 기록](2026-09-21-historical-models.md)에 정리했다.

## 2026-09-21 투수 운용 조건 비교

휴식·최근 3/7일 투구량·경기 내 투구 수·반복 대면의 조건 맞춤 비교를 추가했다. 등록 역할이 없으면
첫 실제 투구/후속 등판이라는 별도의 관측 역할을 사용한다. 기존 등판 응답과 공식 역할은 유지한다.
공통 조건의 지표별 분모·경기 단위 불확실성을 표시하고 부족한 표본은 보류한다. 날짜 창/등판 조회만
공유하며 DB 셀 집계 후 기존 worker로 계산한다. 대면 window와 연결의 반복 실행 병목을 제거했다.

단위/API/UI 873개, DB 74개와 E2E 및 품질 게이트가 통과했다. 실제 6개 선수·시즌의 198개 비교 중
72개가 제공 가능했고, SQL 최적화 전후와 기존 등판 응답의 hash가 유지됐다.
운영에 배포해 새 비교·기존 등판 응답 각 6개를 대조하고 화면의 지표 전환·소표본 보류를 확인했다.
2023–2025 모델 16개와 current/active 파일 11개, 4,693개 sealed revision의 hash는 유지됐다.
[정의·실자료·성능 검증](2026-09-21-workload-comparison.md)에 상세 범위를 기록했다.

## 2026-09-21 전체 시즌 회귀 점검

`analysis:audit` 명령으로 소유권을 확인한 기존 격리 DB를 읽기 전용으로 점검한다. 정규시즌 전체
1,729개 선수·시즌과 실제 1,318,591구의 독립 합계·제외·분모·보류 정책·순서 반전 재계산을 검증했다.
전체 응답 hash가 변경 전후 같았다. 57,057개 비교 중 7,616개를 제공하고 나머지는 표본 정책에 따라
보류한다. 조건 문턱을 완화하지 않았다.

실제 HTTP route의 첫 요청·반복 30회·동시 4건씩 10묶음과 운용 취소 후 복구를 반복 측정한다.
공통 JSON 정렬의 중복 정규화, 일별 보정의 반복 키 생성과 날짜 변환을 줄이고 strict 입력 검증기를
재사용한다. API 계약·모델·보정 수치는 유지한다. 전체 HTTP 지연의 뚜렷한 개선은 확인하지 못했으며,
새 보정 캐시를 만드는 최초 품질 조회 약 10초를 남은 비용으로 명시했다.
[실제 결과와 측정 범위](2026-09-21-full-audit.md)에 기록했다.

단위/API/UI 874개, DB 74개, 검증 도구 7개, 격리 Compose E2E와 품질 게이트가 통과했다.
운영에 반영해 주요 HTTP 응답 3개를 격리 결과와 대조했다. 모델 16개, current/active 파일 11개와
4,693개 sealed revision의 hash를 유지했고 API·웹·DB 준비 상태를 확인했다.

## 2026-09-21 품질 요약 저장·준비

시즌·경기 종류별 경기 요약을 저장하고 기간 필터와 서버 재시작에 재사용한다. 매 조회에서
current revision·분류·유효 신장·계산 정의를 확인해 영향을 받는 시즌만 무효화한다. 미준비 GET은
202 상태를 반환하고 한 작업/대기 16개로 준비하며 화면에서 완료 확인·실패 재시도를 지원한다.
기존 보정 workspace와 worker를 재사용하고 새 서비스나 범용 프레임워크는 만들지 않았다.

기존 HTTP 응답 3종의 hash가 유지됐으며 격리 자료의 새 route 조회는 추가 계산 없이 228ms였다.
단위/API/UI 889개, DB 75개, 도구 7개, 격리 E2E와 기본 품질 게이트를 통과했다. 운영에 반영해
응답과 데스크톱/모바일 기간 선택을 확인했고 기존 모델·원장·봉인 해시를 유지했다.
[계약·측정 범위·운영 기록](2026-09-21-coverage-preparation.md)을 따른다.

운영 API의 실제 재시작 직후에도 저장 요약을 재계산 없이 247ms에 반환했으며 응답·모델·봉인 해시를 재확인했다.
