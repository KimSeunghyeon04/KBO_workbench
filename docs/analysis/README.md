# 분석 기능 확장 설계와 구현 계획

작성일: 2026-09-20. 상태: 첫 범위 구현·실데이터 검증·운영 반영 완료. 실제 반영·검증 범위는 [구현 상태](implementation-status.md)에 기록한다.

현재 수집한 2020–2025 경기로 구현할 분석의 범위, 계산 책임, 데이터 조건과 작업 순서를 정한다.
구현 완료 여부는 코드·기능 문서·테스트를 함께 확인한다. 전체 계획 완료와 개별 단계 검증을 구분한다.

## 읽는 순서

1. [전체 설계](design.md): 권위 경계, 추상화 기준, 표본·좌표·캐시·검증 정책.
2. [자료와 입수 범위](data-sources.md): 현재 데이터, 보완 가능한 자료, 제외 기능.
3. [구현 순서와 배포 단위](implementation-plan.md): 선행 조건, 단계별 산출물과 품질 게이트.
4. 아래 기능별 계획: 계산 정의, 변경 위치, 작업 목록, 회귀 검증과 완료 조건.
5. [실데이터 검증 절차](real-data-validation.md): 격리 snapshot·공식 분류·순차 학습·성능 기록.
6. [운영 배포 기록](production-deployment.md): paired backup·분류/모델 반영·운영 HTTP 점검.
7. [11회 승리확률·조회 개선](2026-09-20-improvements.md): 학습용 종료 재구성·캐시·SQL 검증.
8. [매치업·진입각 확장](2026-09-20-matchup-angles.md): 구질 거리·타자 효과의 시간 검증과 원천 VAA/HAA.
9. [시즌별 모델 운영](model-management.md): 과거 시즌 기간 정책·자동 갱신·작업 복구와 미지원 범위.
10. [운용 조건 비교 검증](2026-09-21-workload-comparison.md): 공통 조건·경기 불확실성·실자료 범위와 조회 비용.
11. [전체 시즌 회귀 점검](2026-09-21-full-audit.md): 전체 투수의 표본·결정론, HTTP 동시 요청과 반복 검증 명령.

12. [품질 요약 준비](2026-09-21-coverage-preparation.md): 저장 요약·비동기 준비·재시작 재사용과 무효화.

선행 조건은 기능 전체 완료를 뜻하지 않는다. 예를 들어 A04는 A07의 기존 코스 정의와 작은 공통
함수만 사용하며, A07 화면 확장을 기다릴 필요가 없다. 단계별 실제 의존성은 구현 순서 문서에 적는다.

## 기존 구현의 출발점

- [투구 움직임](../pitch-shape-analysis.md): 중간면 구장 보정, 평균 포심 기준, GMM과 결과 요약.
- [타자 선구안](../batter-discipline-analysis.md): 실제 코스, 포심 가정, 같은 조건의 다른 타자 비교.
- [스트라이크존](../strike-zone.md): 신장·시즌 기준 및 확정된 키의 출처.
- [PostgreSQL](../postgresql-persistence.md): current sealed revision과 typed fact.
- [검증·성능](../testing-and-performance.md): 기존 품질 게이트와 격리 테스트.

새 범용 분석 엔진, 지표 수식 언어, 플러그인 시스템, 별도 서비스는 만들지 않는다.
각 기능을 끝까지 구현하면서 실제로 같은 의미를 가진 작은 부분만 공유한다.
