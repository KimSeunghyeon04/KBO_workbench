# 타자 선구안 탐색 (modelVersion 1)

## 경기 종류와 두 기간 비교

`competition`, `dateFrom`, `dateTo`, `leaguePeriod=season|target`을 기존 query에 추가했다.
기본은 수집 경기 전체와 시즌 리그 비교군이다. 공식 경기 분류가 바뀌면 reference 및 준비된
시즌의 원천 해시가 바뀐다. 날짜는 대상 투구에 적용하고, `leaguePeriod=target`을 선택하면
다른 타자 비교군도 같은 기간으로 좁힌다. 포심 기준은 같은 시즌·경기 종류 전체로 유지한다.

두 기간 비교 화면은 동일 조건의 기존 API를 재사용한다. 두 결과의 원천 해시가 다르면 비교를
표시하지 않고 다시 조회하게 한다. 표에는 전체·상황 제외·존·지도·공통·조건 일치 표본을 함께
표시한다. 실제 코스 계산 `observedPitchLocation`은 source-plane와 기존 신장 정책을 유지하며
구질용 중간면 보정을 적용하지 않는다.

스트라이크존은 타자 키로 계산한다. 2024년까지는 2024 규칙, 2025·2026년은 2025 규칙을 사용하며
트래킹 존으로 대체하지 않는다. 키가 없으면 계산 불가다. [정책·구현·검증](strike-zone.md)을 따른다.

`/analysis/batter-discipline`에서 시즌(1982–2026)·타자·카운트·중계 구종·타석 좌우를 선택한다.
첫 타자는 시즌 실제 투구 표본이 가장 많은 타자이며 타자·조건은 URL에 저장한다. 서로 다른 요청의
결과를 섞지 않고 계산 중에는 새 결과가 나올 때까지 지도·표를 숨긴다. 현재 작업 영역의 메뉴에
‘타자 선구안’을 제공하며 DB sealed fact는 변경하지 않는다. 신규 수집은 제공자 존 필드를 버린다.

## 분석 대상과 실제 코스

같은 repeatable-read/read-only DB snapshot의 `analytics.current_pitches` 실제 투구를 읽는다.
번트로 기록된 PA, 고의사구 PA, 사구 투구, 번트 파울 투구는 별도 제외 건수로 집계한다. 기록에
없는 작전이나 번트 의도는 추정하지 않는다. 타석 stance L/R/S 및 미상은 원천값을 유지한다.
투수 좌우는 추정하지 않으며 이 버전의 필터·보정 대상에 포함하지 않는다.

실제 좌우는 `cross_plate_x`, 실제 높이는 `y(t)=cross_plate_y`의 최초 전진 교차 시각에서
계산한 `z(t)`다. 존 안팎은 경기 원문·같은 시즌 자료·검토한 공식 프로필에서 DB에 확정한 신장으로
경계를 계산한 SQL `tracking_in_zone`의 판정값을 사용한다. naver_pts_v1,
y0=50, 유한한 값, 양수 비행시간과 전진 교차, 신장으로 계산한 존 경계를 만족하는 위치만 포함한다.
따라서 정지한 공이나 50피트 외 관측까지 포함하는 일반 SQL Zone%와 표본 범위가 다를 수 있다.
초기 좌우 속도 등이 없어 포심 비교가 불가능해도 실제 코스가 유효하면 왼쪽 지도에는 포함한다.

가로는 x/(47.18/2/30.48), 세로는 (z-존 중앙)/(존 높이/2)로 정규화한다. 각 축을
`(-∞,-1),[-1,-1/3),[-1/3,1/3),[1/3,1),[1,∞)`로 나눈 5×5 지도다. 바깥 칸은 더 멀리
벗어난 공도 포함하며, 굵은 선은 실제 존 경계를 나타낸다. 경계에 정확히 걸친 공의 cell과 별개로
존 판정은 SQL의 inclusive 규칙을 유지한다. 칸 선택은 아래 투구 목록만 좁히며 분석 분모는 유지한다.

## 포심 가정

시즌 포심 기준은 동일 sourceHash의 `source-plane` 파일 캐시로 재사용한다. 투구 움직임 분석의
중간면·구장 보정 기준과 별도 키로 저장하며 이 화면의 실제 도착 코스에는 구장 보정을 적용하지 않는다.
저장 경기의 ‘직구’를 포심으로,
좌·우완 합산 및 공마다 동일 가중치를 유지한다. 기존 기준 궤적 모델이나 파일 버전을 변경하지 않는다.

선택 공의 50피트 위치와 초기 방향(vx/vy, vz/vy)을 고정하고 기준 포심의 정렬된 곡률·비행 시계를
적용한다. d는 **대상 공의** y0-crossPlateY, Tff는 `d + 평균 vy*Tff + 평균 ay*Tff²/2=0`의
첫 전진 교차 시각이다. 예상 위치는 다음과 같다.

```text
xFF = x0 - (vx0/vy0)*d + 평균 kx*Tff²/2
zFF = z0 - (vz0/vy0)*d + 평균 kz*Tff²/2
ΔX = (실제 crossPlateX - xFF)*30.48 cm
ΔZ = (실제 z(Ti) - zFF)*30.48 cm
Δt = (Ti - Tff)*1000 ms
```

각 공이 **각자 플레이트에 도착한 때**의 위치를 비교한다. 기존 투구 움직임 화면의 동일 시각
3D 좌표와 정의가 다르며, 두 화면의 편차를 혼용하지 않는다. 초기 위치·방향의 변화는 제거하지 않는다.
실제 가로 관측값과 궤적 적합값의 차이도 ΔX에 포함될 수 있다. 초기 50피트 이전의 비행·시각 정보,
실제 스윙 시작 시각, 타자의 기대나 인식 확률을 측정한 모델이 아니다.

예상 존 안/밖 × 실제 존 안/밖 네 구간과 각 ΔX/ΔZ/Δt의
`(-∞,-40),[-40,-20),[-20,0),[0,20),[20,40),[40,∞)` 구간을 집계한다. 단위는 위치 cm, 시간 ms다.
음의 시간차는 먼저, 양의 시간차는 늦게 도착한다. 기본 포심이 없거나 가정 계산에 실패하면
예상 위치·전이·편차를 null로 남기고, 실제 코스·스윙 지도는 유지한다.

## 리그 비교

각 표는 투구 수, 스윙 수, swingRate=swings/pitches, 헛스윙 수와 whiffRate=whiffs/swings를
계산한다. 분모가 0이면 null이다. 헛스윙은 스윙 선택 이후의 결과로 표시하며 선구안 점수로 합치지 않는다.

선택 타자를 제외한 같은 시즌의 다른 타자를 비교 집단으로 사용한다. 카운트(볼·스트라이크),
중계 구종(미상 별도), stance(미상 별도), 중계 구속 5km/h 구간(미상 별도), 실제 위치 cell과
inZone이 같은 공끼리 비교한다. 전이·편차 표에서는 그 표의 구간도 같아야 한다.
각 조건의 다른 타자 표본이 20구 이상일 때만 비교 가능으로 판정한다. fallback이나 임의 보간은 없다.

리그 스윙률은 각 비교 가능 투구에 대응하는 다른 타자 스윙률의 평균이다. 선택 타자의 투구 구성으로
가중하며, 차이(%p)의 타자 분자·분모도 **같은 비교 가능 표본**만 사용한다. 전체 스윙률과 비교 가능
표본의 스윙률을 구분해서 표시한다. 조건이 희소하면 비교 수·비율은 0/null이며, 최적 판단·인식 확률·
개인 능력의 인과 효과로 해석하지 않는다. 투수 좌우·투수 identity·배합·작전·개인 타격 능력은 미보정이다.

## 구현과 검증

### 기존 코스와 포심 조건 추가 비교

응답의 `courseComparison`을 기존 궤적 modelVersion 1에 추가한다. 기존 계산 정의를 변경하지 않는다.
`conventional`은 같은 선택 필터·상황 제외 기준을 적용한 actual pitch 중 SQL `inZone`이 null이
아닌 공이다. y0=50이나 완전한 초기 좌우 속도를 추가로 요구하지 않는다. 따라서 궤적 지도보다
넓은 표본일 수 있으며, 지도 좌표를 지어내지 않는다. `common`은 포심 예상 존도 계산 가능한 공이다.
둘 다 선택 타자와 다른 타자 합산을 따로 반환한다. 다음 지표는 모두 **존 판정 가능 표본** 기준이다.

- Zone% = zonePitches / pitches, Swing% = swings / pitches
- Z-Swing% = zoneSwings / zonePitches, Chase% = outsideSwings / outsidePitches
- 분모 0은 null. 상단 기본 지표도 conventional 타자 값을 사용한다.

공통 표본의 실제 존 밖 공은 `in-out`과 `out-out`으로 완전히 분할된다. 두 구간의 스윙 수와 공 수를
각각 합산한 비율이 공통 표본 Chase%다. 구간별 스윙률 차이가 전체 지표의 개선을 뜻하지 않는다.

`paired`는 actual outside 전체와 위 두 부분집합을 반환한다. 선택 타자와 리그의 기본 모집단 모두
포심 비교 가능 공으로 제한한다. 코스 비교는 기존 stratum(카운트·구종·stance·5km/h 구간·cell·실제 존)을,
포심 비교는 **같은 stratum + expectedInZone**을 사용한다. 둘 다 다른 타자 표본 20구 이상인 조건에
해당하는 동일한 타자 공만 남긴다. 각 공에 대응하는 리그 스윙률을 평균하며 타자 스윙률·분모는
양쪽에서 같다. 타자−리그 잔차도 같은 표본이다. 전체와 두 부분집합의 matched 수·스윙 수·리그 기대
스윙 수가 가중 합산으로 일치해야 한다. 기존 summary의 비교 표본보다 작아질 수 있다.

이는 표본과 비교 조건을 통제한 기술 통계다. 별도 예측 모델 학습, 교차 검증이나 예측력 개선 평가는
포함하지 않는다. 상대 투수 좌우·투구 배합 등의 기존 미보정 항목도 유지한다.
UI는 기본 지표, 공통 존 밖 공 분해, 동일 표본의 조건 추가 전후 비교 표를 제공한다.
카운트 선택은 0/1/2스트라이크 또는 0/1/2/3볼만으로도 필터하며 URL의 부분 조건을 그대로 복원한다.

### 실행 경로와 검증

- `game-core/batter-discipline`: 위치 복원, 포심 가정, 정규화 코스와 편차 분류, 분모 및 비교 집계.
- `persistence/BatterDisciplineRepository`: sourceHash·기준·시즌 실제 투구를 한 snapshot에서 읽는다.
  같은 시즌/hash가 worker에 있으면 원시 투구·기준 재조회를 생략한다. 처리 전에 DB 연결을 반환한다.
- server의 전용 worker 하나가 최근 시즌의 준비된 표본을 메모리에 보유한다. 시즌·sourceHash 변경 시
  교체하고 재시작하면 다시 읽는다. 계산 대기 최대 16개, 계산 60초 제한, 동일 진행 요청 공유,
  종료 시 대기·진행 요청 거부와 worker 종료를 수행한다. 원시 투구를 파일 캐시에 추가하지 않는다.
  DB 행은 컴파일한 strict validator로 검증하며 2,000행마다 이벤트 루프를 양보한다. worker 전달도
  5,000행 단위로 나눠 전체 시즌의 structured clone이 HTTP 처리를 장시간 막지 않게 한다.
- strict TypeBox DB hydration·API·worker 메시지·웹 응답 검증과 웹의 분모/identity 검증을 사용한다.
- API: `GET /api/v2/analysis/batter-discipline?season=2024` (타자 목록),
  `GET /api/v2/analysis/batter-discipline/:batterId?season=2024&balls=0&strikes=2&pitchType=직구&stance=L`.
  season은 필수, 나머지 필터는 선택 사항이다. 잘못된 값은 400, 계산 대기 포화는 503이다.
- 회귀: 실제/가정 도착 시각·초기 방향·대상 plate plane·누락 baseline·미상 층화·희소 비교군·
  자기 타자 제외·분모 보존·필터·동시 요청·worker 종료·sourceHash/current 변경·UI 응답 역전.
- 격리 PostgreSQL integration 및 E2E에서 실제 fact 읽기, URL 복원, 지도·편차·투구 선택,
  시즌 전환과 390px/1440px 레이아웃을 검증한다.
