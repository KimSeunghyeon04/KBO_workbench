# 시즌 평균 포심 도착 시각의 투구 분석

## 2020–2025 범위와 기간 요약 확장

분석 화면은 2020–2025 시즌과 경기 종류·대상 기간을 지원한다. 기존 화면의 기본 범위는
`competition=all`(수집 경기 전체)이며 `regular`는 공식 일정으로 확인한 경기만 포함한다.
대상 기간은 투수 표본을 좁히고, 평균 포심과 구장 보정은 같은 시즌·경기 종류 전체를 유지한다.
`sourceHash`는 대상 범위를 포함하고 `referenceSourceHash`는 시즌 기준 입력을 식별한다.
캐시 파일은 후자의 해시로 찾는다. 월별 요약은 실제 투구 사용률, 유효 구속 표본, 궤적 표본,
보정 완료 표본을 구분하며 가로/세로 표준편차는 표본 표준편차다.

구질·품질·선구안의 궤적 계산 worker는 `routes/analysis.ts`에서 조립한다. DB 입력을 같은
snapshot에서 읽은 뒤 계산 전에 연결을 반환한다. 관련 설계 및 진행 상태는
[분석 구현 상태](analysis/implementation-status.md)를 따른다.

군집 이전의 투구 표본 조회·궤적 계산도 시즌 sourceHash·투수·모델/reference 버전별로 공유한다.
표본 캐시는 32MiB/32개, idle 5분으로 제한한다. 매 요청 repeatable-read transaction에서 최신
시즌 revision 목록을 확인하며, 최초 loader의 같은 snapshot에서 기준과 투구를 읽는다.
캐시 소비자는 응답 사본을 받고 실패한 계산은 남기지 않는다. 기준·표본 계산은 worker 1개,
대기 16개로 제한하고 5,000행씩 전달하여 큰 시즌의 메시지 복사가 API를 오래 점유하지 않게 한다.

타자별 선택 행동은 [타자 선구안 분석](batter-discipline-analysis.md)의 별도 화면에서 확인한다.
그 화면은 초기 위치·방향을 보존한 각자의 플레이트 도착 위치를 비교하며 이 문서의 동일 시각
정렬 좌표와는 정의가 다르다. 기준 파일 저장 구현은 공유하지만, 타자 선구안은 원천 플레이트면의
미보정 기준(`calibrationHash=null`), 투구 움직임은 중간면의 구장 보정 기준을 별도 키로 저장한다.

`/analysis/pitch-shape`에서 2020–2025 시즌과 투수를 선택한다. 구종 필터는 표시할 점만 좁힌다.
평균 기준은 선택 시즌의 `analytics.current_pitches` 중 실제 투구이며 구종명이 `직구`인 모든
투구다. 좌·우완은 합산하고 투구마다 같은 가중치를 적용한다. 투수와 구종 선택은 기준을 바꾸지
않는다. 저장된 경기 범위의 평균이며 리그 전체 또는 정규시즌만 수집되었다고 가정하지 않는다.

## 좌표와 시간 계약 (modelVersion 2)

길이는 foot, 시간은 second인 `naver_pts_v1` 관측을 사용한다. 입력은
`x0/y0/z0, vx0/vy0/vz0, ax/ay/az, crossPlateY`다. `y0=50`인 관측만 사용하며,
`crossPlateY`는 종방향의 플레이트 위치다. 분석에서는 중간면 `17/24 ft`를 사용하고 원천 fact는 보존한다.
나머지 궤적 값 누락·비유한 수·미지원 profile·전진 교차 불가·음수
플레이트 높이를 제외한다. 자동 판정/no_pitch, 미연결 및 중복 관측은 실제 투구 표본에 추가하지 않는다.

모든 투구의 50피트 기준 시각을 t=0으로 둔다. 초기 위치와 초기 진행 방향을 정렬하기 위해
거리 방향의 초기 접선을 제거한다. 이는 실제 코스·릴리스 위치를 표시하는 그래프가 아니라
정렬된 모델 궤적의 정면 투영이다.

```text
d = y0 - 17/24
kx = ax - (vx0 / vy0) * ay
kz = az - (vz0 / vy0) * ay
kx_corrected = kx - 경기일·구장별 lateralBias
kz_corrected = kz - 경기일·구장별 verticalBias

플레이트까지 종방향 거리: q(t) = d + vy0*t + ay*t²/2
보정된 좌우 위치:         u(t) = kx_corrected*t²/2
보정된 높이:              w(t) = kz_corrected*t²/2
```

`u=x(t)-x0-(vx0/vy0)*(y(t)-y0)`, `w=z(t)-z0-(vz0/vy0)*(y(t)-y0)`이므로 초기
위치와 방향 변경은 제거하면서 원래의 비행 시계와 종방향 구속 차이는 유지된다. 중력 보정 IVB나
측정된 회전수/회전축으로 해석하지 않는다.

유효한 기준 직구의 d, vy0, ay, 보정된 kx, kz를 투구별 동일 가중치로 평균 낸다. 이는 같은 t의 정렬된
좌표를 평균 낸 궤적과 같다. `T`는 평균 q(t)가 0이 되는 최초 전진 교차 시각이다. 개별 투구의
도착 시간 평균과 다르다. 모든 분석 궤적을 중간면에 맞추며 원천 crossPlateY는 수정하지 않는다.
이하 위치 식의 kx/kz는 적용 가능한 일별 구장 편향을 뺀 값이다.

각 공의 실제 모델 도착 시각을 Ti라고 하면 다음을 표시한다.

```text
가로(cm) = (kx - 평균 kx) * T² / 2 * 30.48
세로(cm) = (kz - 평균 kz) * T² / 2 * 30.48
깊이(cm) = q(T) * 30.48
도착 시간차(ms) = (Ti - T) * 1000
```

점 위치는 모두 동일한 T에서 계산한다. 각 공의 Ti로 위치를 계산하거나 먼저 도착한 공을
플레이트에 고정하지 않는다. 시간차 음수이면 먼저 도착, 양수이면 늦게 도착이다. Ti<T인 공은 모델을
플레이트 이후까지 연장한 외삽 위치로 명시한다. 정면에서 가로는 원천 X축의 부호를 유지하고
세로는 양수가 위다. X·Z·종방향 Y를 직교 투영하고 회전할 수 있다. Y 양수는 플레이트 이전이다.
기본 축별 확대는 각 축의 전체 투구 범위로 표시 비율만 조정하며 실제 길이 비율로 전환할 수 있다.
구종·클러스터 필터는 전체 투구로 정한 범위와 카메라를 바꾸지 않는다. 색은 중계 구종 또는 군집이다.

## 3D 군집 (clustering.modelVersion 2)

투수·시즌의 유효한 모든 점의 X·Z·Y만 분포 적합에 사용한다. 시간차·구속·개별 중계 구종은 넣지 않는다.
각 축을 해당 투수·시즌의 평균과 모집단 표준편차로 z-score 표준화한다. 상수 축은 0으로 둔다.
full 공분산 GMM을 고정 K로 적합한다. 기본 K는 이 유효 표본에서 나타난 중계 구종명의 종류 수다.
한 번만 나온 표기도 포함하며 null은 종류 수에서만 제외하고 해당 공은 적합에 포함한다. 모두
미상이면 기본 K=1, 점이 없으면 K=0이며 계산하지 않는다. 범위는 1부터
min(유효 투구 수, max(12, 중계 구종 수))까지다. K를 고정해도 중계별 일대일 대응을 보장하지 않는다.

입력을 원좌표 X/Z/Y 사전식 순서로 정렬한다. seed 42~51의 결정론적 난수와 k-means++/최대 50회
Lloyd 초기화로 10개 후보를 적합한다. EM 최대 500회, 평균 로그우도 차이 허용치 1e-3, 공분산
대각 정규화 1e-5를 사용한다. Cholesky와 log-sum-exp로 계산하며 수렴한 후보 중 로그우도가
가장 높은 결과를 선택한다. 같은 로그우도는 먼저 적합한 후보를 유지한다.
최종 중심 X/Z/Y 순서로 번호를 부여하며 같은 중심은 원래 성분 순서를 사용한다. 각 공은 최대 사후
확률의 성분에 배정하고 확률 동률은 작은 번호를 선택한다. 원래 투구 순서로 라벨을 복원한다.
`componentCount`는 설정 K, `clusterCount`는 실제 배정된 서로 다른 번호의 수다. 빈 성분 때문에
군집 번호에 빈 번호가 있을 수 있다. 성공한 GMM은 모든 공을 배정하며 이는 이상치가 없다는 의미가 아니다.
모든 후보가 미수렴/수치 실패이면 status=not_converged와 null 라벨을 반환한다. 다른 알고리즘이나
더 작은 K로 대체하지 않는다. 점이 없으면 status=empty다. DBSCAN의 noiseCount는 unassignedCount로 대체한다.
번호는 이 표본 안에서만 의미가 있고 투수·시즌·데이터 변경 사이에 같은 구종을 뜻하지 않는다.
`sourceHash`, 궤적 modelVersion, 군집 modelVersion과 설정이 계산 입력을 식별한다. 원표기는 보존한다.
서버 분석 서비스는 DB 읽기와 좌표 생성이 끝나 연결을 반환한 다음 worker에서 GMM을 실행한다.
최대 2개 동시 계산, 최대 32개 대기 요청과 작업당 30초 제한을 두며 서버 종료 시 worker와 대기를
정리한다. 대기열이 가득 차면 503 pitch_analysis_busy를 반환한다. 같은 키의 동시 계산은 공유한다.
키는 시즌·투수·sourceHash·보정 profileHash·궤적 버전·군집 모델 설정·K이며 결과 최대 32개를 LRU 메모리 캐시로
재사용한다. 서버 재시작 후 GMM은 다시 계산하며 시즌 기준 파일 캐시는 그대로 사용한다.
원천 fact 및 sealed revision에는 군집을 저장하지 않는다.

클러스터링 탭의 군집 수 선택은 즉시 재계산하고 URL clusterCount에 수동 값을 저장한다. 생략하면
중계 기본값이며 초기화 버튼은 해당 query를 제거한다. 투수·시즌 변경은 수동 값을 해제하고,
표시 기준 전환은 유지한다. 재계산은 군집 필터를 초기화하되 카메라와 투구 identity 선택을 보존한다.
이전 결과는 계산 중이라는 표시와 함께 흐리게 유지하고 최신 요청의 응답만 반영한다. 중계 구성,
설정 K와 실제 배정 수, 빈 성분·미수렴을 표시한다.

기준 속력은 50피트에서 `hypot(vx0,vy0,vz0)*1.09728` km/h를 평균 낸다. 제공자 중계 구속과 구분한다.
측정 시작점·실제 릴리스 위치·구속의 측정 위치를 추가로 추정하지 않는다.

## 포심을 예상한 타자와의 차이 (expectation modelVersion 1)

평균 포심이 플레이트에 도착하는 T를 예상 타격 시각으로 둔다. 위치는 50피트 초기 위치와 방향을
정렬한 모델이므로 실제 배트와 공의 간격, 타자의 의도, 헛스윙의 원인을 측정한 값이 아니다.
시즌 기준은 저장된 경기의 좌·우완 직구를 합산하며 수집 범위를 유지한다.

같은 snapshot의 유효 기준 포심을 T에서 X/Y/Z(cm)로 비교한다. 원좌표 사전식 정렬 후 평균과
모집단 full 공분산을 계산하고 대각에 0.0001 cm²를 더한다. Cholesky L로 변환해
`r = ||L^-1 (position - mean)||`인 Mahalanobis 거리를 구한다. 정규분포를 가정한 임계값 대신
정렬된 r의 nearest-rank 50%, 90% 분위수로 중첩 타원체를 만든다. 경계 비교 허용 오차는
`1e-10 * max(1, radius)`이며 같은 값은 모두 포함한다. 실제 포함 수를 반환하므로 동률이나
작은 표본에서 목표 포함률을 넘는 것도 표시한다. 유효 포심 4구 미만은 distribution=null이며
영역 비교를 하지 않는다. 공분산 퇴화 축은 정규화로 처리한다. 이 영역은 개별 투구의 표본 포함
영역이며 평균의 신뢰구간, 타격 가능 영역 또는 구종 확률이 아니다.

`referenceDistribution`은 중심, Cholesky 변환, 표본 수, 경계 반경과 포함 수를 제공한다. 각 점은
DB typed `swing`·`whiff`와 `referenceBand`(core50/shell90/outside90 또는 null)를 가진다.
`expectation`은 providerGroups/clusterGroups/bands를 반환한다. 위치·시간 평균과 모집단 표준편차,
90% 밖 투구 수, 스윙/헛스윙 수와 `whiffRate=whiffs/swings`를 계산한다. 스윙 0의 비율은 null,
빈 그룹의 평균/표준편차도 null이다. 분포가 없으면 밖 투구 수는 null이며 bands는 빈 배열이다.
구종 미상과 GMM 미배정도 집계에서 제외하지 않는다. GMM 적합에 결과나 포심 분포를 넣지 않는다.

웹은 안쪽 50% 실선·바깥 90% 점선의 3D 타원체를 표시한다. 분포를 꺼도 축 범위는 유지한다.
표의 구종/군집 행은 표시 필터를 따르며 분포 구간별 집계는 선택 투수·시즌의 전체 유효 투구다.
계산 중에는 새 요약을 표시하지 않는다. 헛스윙률에는 분자/분모와 코스·카운트·타자 좌우 미보정
설명을 함께 제공한다. 좌우·높이·시간차를 하나의 구위 점수로 합치지 않는다.

## 자동 구장 보정 (calibration modelVersion 1)

선택한 연구 모형 `daily_w84_h7`을 사용한다. 경기일 D에는 같은 시즌의 `[D-84일, D)`만 사용한다.
당일 경기와 이후 경기는 계수 추정에 들어가지 않는다. 투수×경기×구종 평균을 만들며 유효 투구가
5구 이상인 셀만 사용한다. 가중치는 `min(투구 수, 30) × 2^(-경과일/7)`이다.
투수×구종×월 고정효과, 구종별 50ft 구속 1·2차항, 좌타 비율, 볼·스트라이크를 통제한다.
둘 이상의 구장에서 관측된 고정효과 집단 중 잠실과 연결되는 비교망만 사용한다.

고척·광주·대구·문학·사직·수원·잠실·창원·대전의 9개 구장 편향 평균을 0으로 둔다.
대전은 2024년까지 구 구장, 2025년부터 신 구장을 별도 identity로 구분한다.
각 구장에 최소 5경기·20투수, 전체 100셀 이상이 필요하며 편향 대비가 식별 가능해야 한다.
구종/구속과 구장이 완전히 겹쳐 편향을 분리할 수 없으면 보정하지 않는다.
수평·수직 계수는 ft/s²로 저장한다. 투수·경기의 이원 군집 공분산과 표준오차도 저장하며
공분산의 음수 고윳값은 0으로 제한한다. 계수 추정에는 공분산 평활화나 역분산 가중을 추가하지 않는다.

운영 초기의 정책은 보수적으로 정했다. 9개 구장 중 하나라도 지원 조건을 충족하지 못하면
해당 날짜 전체를 미보정으로 둔다. 연구 비교에서 일부 부족 구장에 사용한 과거 월/시즌 대체값은
운영 구현에서 사용하지 않는다. 따라서 시즌 초 또는 장기간 경기가 없는 기간까지 연구의 개선율이
그대로 적용된다고 볼 수 없다. 계수가 준비되지 않았거나 미지원 구장이면 해당 공은 유효 표본에
포함하되 `insufficient_data` 또는 `unsupported_park`로 표시한다. 계수가 있는 공은 `applied`다.
화면은 보정/미보정 구수, 선택한 공의 구장과 공통 T에서 차감한 cm를 제공한다.

평균 포심·기준 분포·선택 투수의 점에 모두 같은 날짜별 계수를 적용한다. 구장 비교로 얻은 상대
편향이며 추적 장비와 환경 효과를 완전히 분리한 값이나 물리적 무브먼트의 정답은 아니다.
시즌 포심 기준은 저장된 시즌 전체의 기술적 비교 기준이다. 보정 계수의 과거 자료 제한이
포심 기준까지 실시간 예측용으로 만든다는 의미는 아니다.

보정 파일은 `.data/analysis/pitch-calibration/v1/<season>/<sourceHash>.json`에 저장한다.
각 날짜에는 과거 입력 해시·학습 기간·마지막 학습일·표본 수·상태·구장별 계수·공분산을 기록한다.
새 current revision이 생긴 뒤 첫 분석 요청에서 worker가 자동 갱신한다. 별도 일일 스케줄러는 없다.
동일 키의 요청은 계산을 공유한다. 원천 변경 시 시즌 행을 다시 읽어 집계하지만, 과거 입력 해시가
같은 날짜는 기존 계수를 재사용한다. `latest.json`은 재사용 후보일 뿐이며 날짜별 입력 해시가
일치하지 않으면 사용하지 않는다. 과거 경기 정정은 그 경기가 포함된 이후 84일 창을 무효화한다.
파일의 strict 계약·canonical SHA-256·날짜/지원 조건을 확인하고 writer lock과 atomic write로 저장한다.
분석 표본·기준·GMM 캐시에도 모델 또는 보정 해시를 반영하여 다른 계수가 섞이지 않게 한다.
원천 fact, 재생, 판정 존과 타자 선구안의 실제 도착 코스에는 이 보정을 적용하지 않는다.

## 구현과 무결성

- `game-core/pitch-trajectory`가 정렬·평균·동일 시각 비교, `pitch-clustering`이 군집 계산의 소유자다.
- persistence는 typed current facts만 읽는다. staging hydration/recompile이나 DB fact 변경이 없다.
- 분석 읽기는 repeatable-read/read-only transaction에서 current revision hash와 대상 투구를 조회한다.
  보정 캐시가 없으면 같은 snapshot의 시즌 전체 구종을 한 번 조회하여 보정·기준·대상 표본에 재사용한다.
  보정만 캐시된 경우 필요한 기준 직구와 대상 투수를 조회한다. game ID/pitch sequence 순서를 고정한다.
- sourceHash는 해당 시즌 current game/revision/document hash의 순서 있는 목록을 식별한다.
- 누락·미지원·비정상 트래킹은 제외 건수에 포함한다. 기준 표본 0이면 baseline은 null이다.
- API params/query/response와 DB hydration은 strict TypeBox 계약이다. 웹은 응답의 시즌·투수도 확인한다.
- 구종 필터는 이미 계산된 점에만 적용한다. 브라우저 응답 캐시 key는 시즌·투수·군집 수 선택을 포함한다.
- 캔버스로 깊이 순서대로 점을 그리고 선택 상세는 HTML로 표시한다. 드래그와 탭 선택을 구분하며
  슬라이더 회전·확대, 정면/초기 시점, 클릭·터치·방향키 선택을 지원한다.
- 상단 영역 선택은 데이터 관리와 분석의 메뉴를 구분한다. 경기 재생은 분석 영역에 포함한다.
  영역별 마지막 로컬 경로와 query/hash를 sessionStorage에 저장하고 허용된 경로만 복원한다.
- 기존 analytics/projection 4/4와 DB migration을 유지한다. migration과 데이터 재적재가 필요하지 않다.

## 시즌 기준 저장

서버는 `.data/analysis/pitch-reference/v<modelVersion>/reference-v<referenceVersion>/<calibrationHash 또는 source-plane>/<season>/<sourceHash>.json`에 평균 궤적
계수(d, vy, ay, kx, kz), 평균 속력, 도착 시각 T와 표본 수·제외 수·경기 날짜 범위 및 포심 분포를 저장한다.
referenceVersion=2가 새 분포 계약을 식별한다. 이전 referenceVersion이 없는 캐시 파일은 그대로 보존한다.
원시 투구 행이나 군집 결과는 이 파일에 저장하지 않는다. 유효한 기준이 없는 시즌도 null로 저장한다.

매 요청의 repeatable-read snapshot에서 확인한 시즌·궤적 모델 버전·sourceHash가 모두 맞을 때만
재사용한다. 새 import/기록 정정은 current revision 목록을 바꾸므로 다음 요청에서 새 기준을 만든다.
다른 시즌의 변경은 해당 시즌 키에 영향을 주지 않는다. 서버 재시작 후에도 재사용하며, 동시 요청은
동일한 키의 계산을 공유한다. 캐시 사용 여부는 위치·시간·군집 결과를 바꾸지 않는다.

파일은 strict TypeBox decode와 canonical SHA-256을 검증한다. 누락·손상·키 불일치이면 다시 계산한다.
쓰기에는 기존 workspace writer lock과 fsync/atomic rename을 사용한다. 키마다 별도 파일을 사용하므로
서로 다른 DB snapshot의 요청은 덮어쓰지 않는다. 오래된 파일의 자동 삭제는 하지 않는다. DB fact가
유일한 원천이고 이 파일은 재생성할 수 있다. 계산식을 변경하면 `PITCH_ANALYSIS_MODEL_VERSION`을 올린다.
계수 추정 규칙을 바꿀 때는 `PITCH_CALIBRATION_PARAMETERS.modelVersion`도 올려 과거 계수 캐시를 구분한다.

API:

- `GET /api/v2/analysis/pitch-shape?season=2025`: 시즌 투수 목록과 실제 투구 수
- `GET /api/v2/analysis/pitch-shape/:pitcherId?season=2025&clusterCount=5`: 고정 시즌 기준, 대상의 점과 제외 건수,
  GMM 설정·기본/최대 군집 수·상태·배정 집계. clusterCount는 선택 사항이며 범위를 벗어나면
  400 invalid_pitch_cluster_count를 반환한다. 잘못된 query 형식은 400 invalid_request다.

계산 회귀는 같은 시각의 위치, 평균 궤적의 교차, 초기 접선 불변성, 시간차 부호·외삽을 검증한다.
PostgreSQL 회귀는 시즌 분리, 선택 투수와 독립인 기준, missing/invalid 분모, current-only revision과
sourceHash 변경을 검증한다. UI 회귀는 시즌 전환, 구종 필터, 키보드 선택과 기준 표본 부재를 확인한다.
저장 회귀는 동시 요청, 재시작 후 재사용, 손상 복구, writer lock, 시즌/revision 분리와 캐시 유무의
응답 전체 동등성을 확인한다.
