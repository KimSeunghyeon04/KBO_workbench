# 선수 리포트의 핵심 기록 위계 개선

## 범위와 판단

선수 리포트의 기본 기록 화면과 공통 선수 탐색을 Impeccable layout 및 kbo-analysis-ui 기준으로
검토했다. 별도의 읽기 전용 레이아웃 평가와 기계 검사를 수행했고, 브라우저 점검 결과를 구현에
반영했다. 흰 작업면·녹색 강조의 기존 디자인과 통계·조회 계약은 유지한다.

기존 화면에서는 제목·조건·독립 안내문 뒤에 핵심 수치가 나왔다. 390×844 화면에서 첫 팀의
핵심 기록 시작점은 약 770px였다. 조건과 상세 기록을 접고 모바일 탐색을 한 줄로 바꾼 뒤에는
약 441px에서 시작하고 네 지표가 첫 화면에 들어온다.

## 변경

- 팀별 타격·투구 핵심 기록을 기본으로 펼친다. 서버의 팀별 행과 비율은 합산하지 않는다.
- 조회 조건은 native details에서 연다. 접힌 상태에도 시즌·경기 종류·기간이 보인다.
- 상세 표와 G·OPS·ERA·분모 안내는 별도의 native details에서 확인한다.
- 미확정 ERA의 자책점 확인 경기 수와 설명을 ERA 값 바로 아래에 표시한다.
- 모바일 분석 항목은 가로 스크롤한다. 직접 URL 진입과 크기 변경에서도 현재 항목이 보이도록
  탐색 줄만 이동하며 문서의 세로 위치를 바꾸지 않는다.

## 브라우저 증거와 한계

로컬 API와 Docker가 실행 중이지 않아 운영 DB 대신 기존 비식별 테스트의 선수·팀·기록을
제공하는 임시 localhost API와 실제 Vite 앱을 사용했다. 운영 데이터의 표시나 DB 통합 검증으로
해석하지 않는다. 임시 서버와 브라우저 탭은 점검 뒤 종료했다.

데스크톱 1280×720과 모바일 390×844에서 투수·타자, 팀별 이적 기록, ERA 미확정, 긴 선수 이름,
빈 기록, 조건 변경과 상세 펼치기를 확인했다. 키보드 Enter로 상세 표를 열었고, 넓은 표는 자체
영역에서 스크롤하며 페이지 전체가 가로로 넘치지 않았다. 분석 항목 간 선수·시즌·범위 보존은
기존 탐색 테스트로도 검증했다. 다른 분석 항목의 통계 결과 자체는 이번 점검 범위가 아니다.

로컬 캡처와 검사 결과는 무시되는 `test-results/impeccable-player-report/`에 보관했다.

## 검증

- 관련 UI·탐색 테스트: 29개 통과. 새 회귀 검증은 기본 접힘, ERA 설명, 기존 상세 값과 조건
  접근, 펼치기에서 추가 요청이 없는 동작을 확인한다.
- 전체 테스트: 198개 파일 통과, 2개 파일 건너뜀. 1,230개 테스트 통과, 76개 건너뜀.
  첫 실행의 임시 파일 rename·localhost 소켓 제한을 해제한 환경에서 재실행했다.
- 변경 파일 lint, 전체 format check, typecheck, schema:game:check, build, git diff --check 통과.
- 전체 lint는 수정 범위 밖 `analysis/validation/20261003-swing-decisions/`의 스크립트와
  의존성 복사본에서 104개 오류로 실패했다. 해당 파일과 lint 설정은 변경하지 않았다.
- Impeccable: 차단 0개. 기존 머리글 글자 크기 관련 권고 4개는 이번 변경에서 유지한 값이며,
  새 탐색 동작 파일의 추가 검사에는 지적이 없었다.

통계·서버·DB 계약이나 영속 동작은 변경하지 않았다. PostgreSQL integration과 Compose E2E는
이번 UI 변경에서 실행하지 않았다.
