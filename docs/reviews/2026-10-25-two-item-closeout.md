# 확인된 두 항목 종료 검증

사용자 요청에 따라 이미 확인된 두 항목만 수정했다. 이전 검증과 같은 비식별 메모리 fixture,
1280×720 데스크톱과 390×844 모바일, 같은 사용 경로로 회귀를 확인했다.

| 항목                                        | 변경                                                        | 고정 경로의 실제 브라우저 결과                                                                                      |
| ------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 리그 성적 최소 표본으로 생긴 빈 결과        | 현재 조건 기준의 빈 결과임을 안내하고 `최소 표본 해제` 제공 | 두 크기에서 4행 → 세부 조건의 최소 9타석 → 0행 → 해제 → 동일한 4행 복원. 모바일 버튼 높이 44px, 문서 가로 넘침 없음 |
| 선택 투구 재생 링크와 근거 ID의 시각적 결합 | ID를 별도 블록으로 표시하고 상단 여백 8px 적용              | 두 크기에서 링크와 ID의 실제 경계 간격 9.39px. `test-game · revision 1 · e2` 유지, 문서 가로 넘침 없음              |

리그 경로는 `/analysis/statistics`에서 시작했다. 최소 표본 해제는 `minimum`과 `page`만
제거한다. 타격·투구 각각의 회귀 테스트에서 시즌, 경기 종류, 성적 종류, 기간, 집계, 정렬을
보존하고 표본 제한이 0인 요청으로 결과를 복원하는 것을 확인했다.

선택 투구 경로는
`/analysis/pitch-shape?season=2025&pitcher=hp1&competition=all`에서 그래프의 Home 키로
e2를 선택했다. `선택한 투구 재생`은 두 크기 모두
`/replay?gameId=test-game&revision=1&eventId=e2`를 열었고, 재생 위치는 2(3/16 장면)였다.
`분석으로 돌아가기`는 같은 선수와 조회 조건의 출발 화면으로 복귀했다.

## 검증

- 관련 회귀 4개 파일, 55개 테스트 통과. 최소 표본 해제의 타격·투구 회귀 2개 추가.
- 전체 테스트 202개 파일, 1,287개 통과. PostgreSQL 통합 2개 파일의 76개 테스트는 DSN 미설정으로 skip했다.
- `format:check`, `typecheck`, `schema:game:check`, `build`, 웹 소스·테스트 ESLint 통과.
- 저장소 전체 `lint`는 기존 104개 오류로 실패했다. 직전 작업 로그와 오류 행을 비교한 차이는 0개다.
- 시작 시점의 웹 소스 190개와 비교해 변경된 소스는 성적 페이지와 관련 CSS 2개뿐이다.
- `git diff --check` 통과. `.env`, `.data`, `.backups`의 Git 변경 없음.
- 검증용 탭과 메모리 API·Vite를 종료하고 화면 크기를 복원했다. 3000·5173 포트 리스너 없음.

증거는 `test-results/impeccable-two-item-closeout/`에 저장했다.
`browser/evidence.json`에는 네 경로의 조건·URL·복원 행 수·간격·재생 위치가 있다.
`browser/01`~`08` 이미지는 원본 브라우저 캡처다. `final-audit.json`에는 소스 해시 비교,
기존 lint 오류 비교, 데이터 경로 상태와 임시 포트 정리를 기록했다.

두 항목의 고정 회귀 경로가 통과했다. 전체 critique와 새 문제 탐색 없이 이 범위에서 종료한다.
