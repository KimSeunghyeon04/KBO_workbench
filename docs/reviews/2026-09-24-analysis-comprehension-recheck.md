# 분석 UI 이해도 재점검 — 2026-09-24

## 결론과 범위

선수·분석 조건·단위·분모는 이전 점검 때보다 명확해졌다. 특히 투구 성과의 분모,
최근 변화의 구종별 요약과 소표본 상태, 배합의 활성 조건 및 유효 쌍 설명은 도움이 된다.
남은 문제는 작은 표본과 큰 표본의 표현 차이, 보정 좌표의 의미, 결과에서 근거 장면으로
이어지는 동선이다. 일부 화면에서는 설명과 원시 표가 핵심 결과보다 먼저 보여 해석 부담도 크다.

- 대상: 배포된 운영 UI `http://127.0.0.1:8080`.
- 방법: 실제 브라우저에서 선수 선택, 조건 변경, 표 행 선택, 근거 링크와 재생을 조작하고
  Graft로 찾은 관련 코드와 대조했다.
- 확인 화면: 선수 목록, 투구 성과/코스, 타자 프로필, 투수 운용, 투타 매치업, 구장 환경,
  투구 배합, 최근 변화 및 근거 확인을 위한 재생 화면.
- 대표 범위: 2025 정규시즌, 투수 손주영(67143). 타자 프로필은 김도영(52605),
  매치업 상대는 구자욱을 확인했다.
- 화면 크기: 데스크톱 1266×713, 배합 표는 390×844에서도 확인했다.
- 한계: 대표 사용 흐름에 대한 이해도 점검이다. 모든 선수·시즌 조합이나 통계 계산의
  정확성을 전수 검증한 결과는 아니다.

이번 점검에서는 애플리케이션 코드·데이터·배포 상태를 변경하지 않았다. 아래 항목은
관찰된 동작과 그에 대한 개선 제안이며, 새 계산 오류가 확인됐다는 뜻은 아니다.

## 이전 개선에서 확인한 효과

- 투구 성과 요약은 Whiff%의 스윙 수와 헛스윙 수, CSW의 투구 분모,
  PutAway%의 2스트라이크 투구 수와 삼진 수를 함께 보여 준다.
- 코스 지도는 포수 시점과 존 밖 영역을 설명한다. 20스윙 미만 셀은 회색으로 구분하고,
  선택하면 실제 스윙·헛스윙 수와 소표본 안내가 나온다.
- 배합 필터가 접혀 있어도 `2스트라이크`, `이전 구종: 직구` 같은 활성 조건을 볼 수 있다.
  기하 지표는 계산 가능한 유효 쌍을 설명한다.
- 최근 변화는 전체 투구와 보정 가능한 투구를 구분하고, 구종별 단위·표본·불확실성을 표시한다.
- 타자 프로필의 공식 타석 표는 투구 조건을 적용하지 않는다는 문구를 바로 위에 표시한다.
  따라서 투구 필터를 바꿔도 공식 타석 수가 유지되는 동작 자체는 문제로 분류하지 않았다.
- 매치업의 루킹 비율은 투구를 분모로 설명한다. 직접 상대와 유사 조건 표본이 겹칠 수 있다는
  설명도 있으므로 두 집단을 합산해야 하는 구조로 읽히지는 않는다.

### 1. P2 — 소표본 비율이 큰 표본과 같은 확실성으로 보인다

**관찰:** 손주영–구자욱 직접 상대 표본은 13구·2경기·5스윙·헛스윙 0회이며 Whiff%는
0.0%다. 유사 조건 표본은 1,420구·582스윙·100헛스윙, 17.2%다. 두 행의 숫자 표현은
동일하고 직접 상대 행에는 소표본 상태가 없다. 분모는 표에 있으나 사용자가 스스로 판단해야 한다.
투구 성과의 간략 구종 표에서도 15구짜리 체인지업의 Whiff 0.0%가 큰 표본의 구종과
같은 방식으로 표시된다. 상세 지표를 열어 수를 확인하는 기능은 있다.

**영향:** 관찰된 0회가 안정적인 헛스윙 억제 능력처럼 읽힐 수 있다. 최근 변화와 코스 지도는
이미 소표본을 구분하므로 화면 간 표현도 일관되지 않다.

**제안:** 비율과 해당 분모를 가까이 배치하고, 지표별로 정한 기준에 따라 소표본 상태를 함께
표시한다. `0/5스윙 · 표본 부족`처럼 관찰 사실을 유지한다. 모든 비율에 하나의 투구 수
기준을 적용하지 말고 실제 분모에 맞춘다.

**완료 확인:** 0/5와 0/500을 구분할 수 있고, 분모 0은 0%로 표현하지 않으며,
상세 표를 열지 않아도 작은 표본임을 알 수 있어야 한다.

근거: `apps/web/src/pages/matchup-page.tsx:130–143`,
`apps/web/src/analysis/pitch-rate-table.tsx:128–240`.

### 2. P2 — 최근 변화의 보정 좌표는 단위가 있어도 의미를 해석하기 어렵다

**관찰:** `보정 세로` 선택 시 직구 카드에 −4.96cm, 이전 −0.90cm → 최근 −5.86cm가
표시된다. 최근 35구/2경기와 이전 239구/5경기, 소표본 보류 상태는 명확하다.
하지만 이 값의 기준 원점과 음수 방향은 카드나 주변 설명에 나오지 않는다.
`보정 가로`, `보정 도착 시간`도 같은 문제가 있다.

**영향:** 도착 위치, 무브먼트, IVB, 기준 구종 대비 좌표 중 무엇인지 사용자가 이름만으로
추측하게 된다. 소표본 안내를 읽더라도 변화 자체의 물리적 의미는 알기 어렵다.

**제안:** 기존 구종 궤적 분석의 좌표 정의를 재사용해 비교 기준·원점·방향과 차이의 부호를
지표 선택부와 요약에 설명한다. `낮아졌다`, `떠올랐다` 같은 문구는 실제 좌표 정의를 확인한
뒤 적용하고, 서로 다른 물리량을 같은 무브먼트 용어로 합치지 않는다.

**완료 확인:** 사용자가 −4.96cm를 무엇에 대한 어떤 방향의 차이인지 설명할 수 있어야 한다.

근거: `apps/web/src/analysis/pitch-change-metrics.ts:6–12`,
`apps/web/src/analysis/pitcher-change-summary.tsx:109–162`,
`apps/web/src/pages/pitcher-changes-page.tsx:65–108`.

### 3. P2 — 특정 타석의 근거 링크가 그 장면으로 연결되지 않는다

**재현:** 매치업의 `2025-09-20 · 20250920SSLG02025:relay_006:7:0 · fielder_choice · r2`
링크를 클릭했다. 재생 화면에는 해당 경기와 revision 2가 선택되지만 별도로 재생 불러오기를
눌러야 한다. 불러온 뒤에도 선택했던 타석이 아닌 `1/604 · 1회초 · 이닝 시작`에서 열린다.

**영향:** 분석 수치의 근거를 검토하려는 사람이 수백 프레임에서 해당 타석을 다시 찾아야 한다.
경기와 revision 연결은 정확하지만 타석까지 이어지는 연결이 부족하다.

**제안:** 근거 링크에 안정적인 타석/이벤트 식별자를 전달한다. 기존 재생 페이지의 manifest와
frame 검증을 모두 통과한 뒤 해당 항목을 포함한 frame으로 이동한다. 찾지 못하면 명시적으로
알리고 경기 처음으로 이동한 사실을 숨기지 않는다.

**완료 확인:** 동일 링크에서 해당 revision의 해당 타석이 열리고, 변경되거나 없는 식별자도
잘못된 장면으로 조용히 연결되지 않아야 한다.

근거: `apps/web/src/pages/matchup-page.tsx:154–159`,
`apps/web/src/replay/use-replay-page-controller.ts:21–23,115–125`.

### 4. P2 — 배합의 궤적 비교 버튼을 눌러도 결과가 보이는 곳으로 이어지지 않는다

**재현:** 손주영·2스트라이크·이전 직구 조건에서 직구→커브 조합을 선택하고,
개별 쌍 표의 두 번째 `궤적 비교`를 클릭했다. 비교 차트는 20행 표와 페이지 이동 버튼
뒤에 있어 화면 밖에 남았다. 클릭 후 수평 궤적 차트의 상단은 뷰포트 위쪽 기준 약
1,276px였고 화면 높이는 713px였다. 선택된 쌍을 지속적으로 식별할 표시도 약하다.

**영향:** 버튼이 작동했는지, 어떤 쌍이 선택됐는지, 어디에서 결과를 읽어야 하는지 불명확하다.

**제안:** 선택 행을 표시하고 날짜·이닝·구종으로 선택 요약을 제공한다. 비교 패널을 가까이
배치하거나 결과 영역으로 스크롤과 키보드 포커스를 연결한다. 실제 두 공의 비교라는 점도 유지한다.

**완료 확인:** 마우스와 키보드로 다른 쌍을 선택할 때 결과 변경 및 현재 선택을 즉시 알 수 있어야 한다.

근거: `apps/web/src/analysis/pitch-sequence-pairs.tsx:158–170,190–219`.

### 5. P2 — 근거 목록의 주된 정보가 내부 식별자와 영문 코드다

**관찰:** 매치업 타석 목록에는 긴 `gameId:relay_...`와 `field_out`, `sacrifice_fly`,
`fielder_choice`가 나온다. 배합의 개별 쌍 표도 긴 투구 ID 두 개와 `called_strike`,
`swinging_strike`, `in_play` 같은 코드를 중심으로 표시한다.

**영향:** 추적에는 유용하지만 타석을 읽고 기억하거나 서로 비교하는 데는 부담이 된다.
특히 좁은 화면에서 식별자가 공간을 많이 차지한다.

**제안:** 이미 응답이 제공하는 경기 날짜·이닝·선수·구종·판정의 한국어 표기를 우선한다.
원본 ID는 근거 상세나 복사 기능으로 보존한다. 부족한 문맥은 클라이언트에서 추측하지 않고
필요할 경우 기존 typed fact를 통해 제공한다.

**완료 확인:** 내부 ID를 해석하지 않아도 어떤 투구/타석인지 구별할 수 있고, 정확한 식별자는
여전히 확인할 수 있어야 한다.

근거: `apps/web/src/pages/matchup-page.tsx:154–159`,
`apps/web/src/analysis/pitch-sequence-pairs.tsx:158–177`.

### 6. P2 — 모델 제공 상태와 해석 요약보다 긴 표·방법 설명이 먼저 보인다

**관찰:** 구장 환경 화면은 720경기의 관측 표를 길게 보여 준 뒤 `팀 구성 조정` 영역에서
현재 원천에 맞는 학습 모델이 없다는 사실을 알린다. 상단에도 단순 평균의 한계를 설명하지만,
지금 조정 지수를 제공하는지 여부는 뒤에서 확인하게 된다.
투수 운용의 조정 비교는 긴 방법 설명 뒤에 결과가 나오고, 신뢰구간이 0을 포함하는 경우에도
표본 상태인 `비교 가능`이 표시된다. 예를 들어 26–50구의 구속 차이는 +0.28km/h,
구간은 −0.09~+0.64km/h다. `비교 가능`은 차이의 방향이 확실하다는 뜻이 아니다.

**영향:** 관측값과 조정값을 구분하거나, 비교할 자료가 있다는 것과 변화 방향이 뚜렷하다는
것을 구분하려면 설명 전체와 숫자를 직접 해석해야 한다.

**제안:** 구장 화면 상단에 `조정 지수 미제공 · 현재 관측 성적만 제공` 상태를 표시한다.
전체 요약을 먼저 보여 주고 홈/원정 세부 행과 긴 방법 설명은 펼쳐 볼 수 있게 한다.
투수 운용은 표본 충족 여부와 변화 방향의 불확실성을 별개로 표현한다. 최근 변화 화면의
요약 패턴을 참고하되 통계 계산이나 인과 해석을 브라우저에 새로 만들지 않는다.

**완료 확인:** 첫 결과 영역에서 현재 제공하는 결과의 종류와 해석 한계를 파악할 수 있어야 한다.
구간이 0을 포함하는 +0.28km/h를 확정적인 구속 상승으로 요약해서는 안 된다.

근거: `apps/web/src/pages/park-environment-page.tsx:49–122`,
`apps/web/src/analysis/workload-comparison-panel.tsx:27–202`.

### 7. P2 — 모바일에서 배합 표를 가로로 이동하면 행의 정체성을 잃는다

**재현:** 390×844 화면에서 두 구종 조합 표를 오른쪽으로 스크롤하면 평균 면 간격·도달
시간차 등의 열은 읽을 수 있지만 왼쪽 구종 조합 이름이 사라진다.
페이지 전체의 가로 넘침은 아니며, 표의 스크롤 영역 자체는 동작한다.

**영향:** 수치가 어느 조합에 속하는지 확인하려면 좌우로 반복해서 움직여야 한다.

**제안:** 첫 행 제목 열을 고정하거나, 작은 화면에서는 선택한 지표와 조합을 함께 보여 주는
간략 표를 제공한다. 여러 열을 무조건 줄여 단위와 분모를 생략하는 방식은 피한다.

**완료 확인:** 오른쪽 끝 지표를 읽을 때도 해당 구종 조합이 항상 보이고 키보드 스크롤도 가능해야 한다.

근거: 실제 모바일 뷰포트 관찰 및 `apps/web/src/analysis/pitch-sequence-pairs.tsx:25–264`.

### 8. P3 — 주요 비율의 수준을 판단할 비교 기준이 부족하다

**관찰:** 손주영의 요약 카드에 Whiff 19.9%, CSW 28.6%, PutAway 17.9%와 정확한
분모가 있지만 해당 위치에서 리그나 선수의 다른 기간과 비교하는 기준은 보이지 않는다.

**영향:** 수치는 이해할 수 있어도 선수의 강점인지, 보통 수준인지 판단하려면 다른 화면이나
외부 지식이 필요하다. 이는 계산 오류가 아니라 분석 해석을 보강하는 기능 제안이다.

**제안:** 분석 목적에 맞는 비교 집단을 명시한 기준을 추가한다. 시즌·대회·구종·선택 조건의
