## 선수 리포트와 표본의 의미

`PlayerAnalysisFrame`은 이름·선수 ID·투수/타자·시즌·경기 종류·기간을 리포트 머리글에 표시한다.
오른쪽의 `범위 내 투구` 또는 `범위 내 상대 투구`는 기존 catalog에서 읽은 해당 선수의 실제 투구
수다. catalog query의 범위는 시즌·경기 종류·시작일·종료일이며, 구종·타석 좌우·카운트·cohort 같은
개별 분석 조건은 포함하지 않는다.

따라서 머리글 표본은 현재 분석 결과의 분모가 아니다. 아래의 `분석 투구`, 스윙 수, 존 판정 가능
투구 수 등은 현재 상황 조건을 적용한 응답에서 따로 표시한다. 좌타자나 2스트라이크 조건을 바꾸면
결과 표본은 달라질 수 있지만 공통 범위의 catalog 표본은 그대로다. 자료가 없거나 범위가 잘못된
경우 머리글에 추정 수치를 만들지 않는다.

공통 프레임은 같은 catalog query를 `enabled: false` observer로 관찰한다. 조회와 선수 결정은
기존 페이지가 계속 소유하며 머리글을 위해 추가 요청이나 다른 분석의 선행 계산을 시작하지 않는다.

`선수 분석 항목`은 실제 주소로 이동하는 링크다. 현재 항목은 대비와 `aria-current`로 표시한다.
같은 항목을 다시 눌러도 현재 query를 보존한다. 다른 항목으로 이동할 때는 선수·시즌·실효 경기
종류·기간을 유지하고 기능 고유 조건은 옮기지 않는다. 매치업에는 `playerRole`을 함께 전달한다.
`선수 변경`도 같은 역할과 범위의 목록으로 돌아간다. 기존 직접 주소와 작업 영역별 마지막 주소
복원 정책은 유지한다.

## 빠른 상황 조건과 URL

코스·결정구와 타자 반응 화면은 기본 조회줄 아래에 타석 좌우와 카운트 바로 선택을 제공한다.
빠른 조건은 별도 필터 상태를 만들지 않고 현재 URL을 복사해 한 번에 변경한다.

- `초구`는 `balls=0`과 `strikes=0`을 함께 설정한다.
- `2스트라이크`는 `balls`를 제거하고 `strikes=2`를 함께 설정한다. 이전 볼 조건이 남지 않는다.
- `전체 카운트`는 두 카운트 조건을 함께 제거한다.
- 조건 칩은 표시한 키 하나만 제거하며, `0볼`과 `0스트라이크`도 유효한 조건으로 표시한다.
- `상황 조건 초기화`는 `pitchType`, `stance`, `balls`, `strikes`, `cohort`만 제거한다. 선수·시즌·
  경기 종류·기간 및 관련 없는 query는 보존한다. 적용된 상황 조건이 없으면 빈 조건 줄을 숨긴다.

`PitchOutcomeQuickFilters`는 다음 URL 파라미터만 부모에 전달한다. 입력 검증, 분석 query와 취소는
`PitchOutcomesPage`가 소유한다. 버튼의 `aria-pressed`와 칩 표시도 URL에서 읽으므로 뒤로 가기와
직접 주소 접근이 같은 상태를 만든다.

## 표 읽기와 화면 밀도

`PitchRateTable`의 열 제목은 내림차순·오름차순을 전환하는 기본 버튼이다. 정렬 방향은
`aria-sort`와 화살표로 함께 표시하고 새 열을 선택하면 내림차순부터 시작한다. 정렬에는 포맷된
문자열이나 반올림된 비율을 쓰지 않고 서버 응답의 숫자값을 사용한다.

- 분모가 없어 `null`인 비율은 `—`로 표시하고 양방향 정렬 모두 마지막에 둔다. 실제 0은 숫자로
  비교한다.
- 동률과 `null`끼리는 응답의 원래 행 순서를 유지한다. 입력 배열을 변경하지 않는다.
- 구종·카운트·타석 좌우·타자의 구속대 그룹을 바꿔도 선택한 정렬을 새 그룹의 행에 적용한다.
- `상세 지표`를 접어 현재 정렬 열이 숨겨지면 정렬을 해제하고 원래 행 순서를 복원한다. 기본
  표시에도 남는 열의 정렬은 유지한다.

`지표 안내`는 native `details`/`summary`이며 현재 보이는 열의 정의와 분모를 설명한다. Whiff%는
헛스윙/스윙, SwStr%는 헛스윙/실제 투구, 결정구%는 삼진 종결 실제 투구/2스트라이크 실제 투구다.
인플레이 안타 비율은 연결된 종결 인플레이 결과를 분모로 삼으며 공식 타율과 구분한다. 설명을
열거나 정렬·그룹·상세 열을 바꾸는 동작은 이미 받은 응답의 표현이며 추가 요청을 만들지 않는다.
행 정렬은 응답과 정렬 조건이 바뀔 때만 다시 계산한다.

선수 목록과 패널의 여백·모서리 반경을 줄이고 숫자는 자릿수 비교가 쉽도록 맞춘다. 표의 행 이름은
가로 스크롤 중에도 고정한다. 코스 화면은 비교 표를 지도보다 먼저 배치하고 viewport 너비 1,500px
이상에서 표와 지도를 두 열로 나란히 표시한다. 그보다 좁으면 세로로 배치하며 넓은 표는 내부에서
스크롤한다. 640px 이하에서는 리포트 머리글의 ID와 catalog 표본을 생략하고 선수 이름·유형·범위와
항목 탐색을 유지한다.

새 범용 표 프레임워크나 통계 계산 계층은 추가하지 않았다. API 계약, compiler 권위, sealed fact,
분석 모델과 수집 경로는 변경하지 않았다.

## 검증

실브라우저에서 손주영 2025년 화면의 catalog 표본 2,496구를 확인했다. 우타자 → 초구 →
2스트라이크 → 초기화 조작 후 선수·조회 범위가 유지되는지 확인했고, Whiff%의 양방향 정렬과
`지표 안내`를 Enter로 열고 Space로 닫는 native 동작도 확인했다. 390px에서 문서 가로 넘침이 없었다.
실제 자료는 읽기만 했다.

회귀 테스트는 빠른 조건의 원자적 URL 갱신·칩별 해제·초기화 범위, 반올림 전 값과 큰 숫자의 정렬,
`null`·동률·숨긴 열 처리, 그룹 전환과 불필요한 요청 없음을 다룬다. 격리 Compose의 기존 선수 탐색
여정에는 같은 선수·범위에서 빠른 조건과 정렬을 조작하는 시나리오를 추가했다. 각 입력 뒤 예상
URL 또는 접근성 상태까지 기다리며 2스트라이크는 한 번의 URL 전환으로 두 카운트 키가 함께
변경되는지 확인한다.

전체 단위 테스트는 182개 파일의 1,006개 테스트가 통과했다. DB DSN이 없는 기본 실행에서
PostgreSQL 관련 75개 테스트는 건너뛰었다. lint, format, typecheck, schema check, build와
`git diff --check`도 통과했다.

격리 Compose E2E는 `kbo-stage6-49956-7cb7c7c0` 프로젝트에서 종료 코드 0으로 완료했다.
선수 탐색·범위 유지·빠른 조건·표 정렬, 기존 운영 화면과 분석 화면, 여섯 모델 worker의 게시·
멱등성·재시작 후 보존을 확인했다. 첫 실행에서 초기화 후 숨겨진 버튼을 찾던 테스트 선택자를
수정한 뒤 전체 시나리오를 다시 실행했다. 실행 로그는 로컬
`analysis/commit-preparation/20260923-reference-ux/e2e-rerun.log`에 남겼으며 이 테스트가 만든
컨테이너·네트워크·볼륨만 정리했다.
