# 프론트엔드 전반 Impeccable 개선

## 상태와 환경

전체 화면의 구현·브라우저 검토·관련 품질 검사와 실행 자원 정리를 마쳤다. 전체 lint의 기존 실패는 아래에 별도 기록했다.

기준 상태는 `test-results/impeccable-frontend-goal/baseline/`에 git 상태·diff와 웹 소스·UI 테스트 사본으로 보존했다. 앞선 선수 기본 기록 개선과 기존 미커밋 변경을 포함한 상태와 비교했다.

- 기존23개 route, 별칭 제외22개 화면을 검토했다. 투수·타자 기본 기록, 타자 탐색·긴 이름과 알 수 없는 주소도 확인했다.
- 실제 브라우저의 데스크톱1280×720·모바일390×844에서 검증했다.
- 운영 API와 Docker가 없는 환경이므로 strict 계약을 통과하는 비식별 localhost 미리보기를 사용했다. 수집·적재·보정은 메모리 fixture에서만 실행했다. 실제 PostgreSQL·Naver·운영 원장의 검증 결과가 아니다.
- fixture는 기존 golden 원장을 공용 컴파일러로 처리한 경기·투구·타석·play identity를 공유한다. 분석 strict 검증70개, 실제 근거 참조768개, 관리 의미·계약 검증112개와 실제 correction 클라이언트16개 요청을 별도 확인했다. 임시 파일은 `test-results` 아래 있으며 제품 코드에 포함되지 않는다.

## 핵심 동작과 경계 사례

- 탐색→투수 리포트, 타자2→선구안 이동에서 선수 ID·시즌·경기 범위를 유지했다. summary를 Enter로 열고 닫고, 경기 종류를 변경한 뒤 다른 리포트에서도 같은 범위를 확인했다.
- 이전 시즌 비교를 명시적으로 열어 현재 조건·2024시즌 분모와 분모0의 `—`를 확인했다. 배합 근거 `/replay?gameId=g1&revision=1&eventId=e3`는 요청 장면 안내와 index3으로 연결됐다.
- 16장면 재생의 처음·다음·끝 경계와 경기 변경 중 기존 상황판 유지를 확인했다.
- 분석·설정의 오류 fixture에서 alert·버튼을 확인한 뒤 정상 응답으로 되돌리고 명시적으로 회복했다.
- 빈2020시즌·0쌍·소표본·분모0·좌표/모델/ERA 미제공과 긴 선수 이름을 확인했다.
- DB 초기화 Enter 뒤 검색창에 포커스가 남았다. 실행 선택과 표시 필터는 분리되었다. 격리 수집·적재는 선택1건과 결과1건이 일치하며 실패 이력은 해당 원인으로 연결됐다.
- 기록정정 공지에서 보정 draft를 열었다. 새 correction 세션에서 문구 명령→undo→redo가 동작했다. 차단 원장은 허용 체크 전 저장이 비활성, 체크 후 quarantine으로만 저장되었다.
- 모바일 drawer는390px 안에 들어가고 포커스를 안에 두었다. Escape 뒤 원래 `수정` 버튼으로 복귀했다. 모바일 메뉴도 Enter/Escape와 포커스 복귀를 확인했다.
- 보정 세션 중 HMR로 서버 세션이 닫힌 미리보기 사례는 새 세션에서 재검증했다. 제품 수정 근거로 취급하지 않았다. 마지막 브라우저 콘솔 warn/error는0개였다.

## 독립 평가와 기계 검사

초기 설계·소스 평가, 실제 브라우저 배치 검토, 독립 시각 재검토, 기계 검사를 구분했다. 변경을 묶어 점검하고 필수 보완 후 확인했으며 취향에 따른 반복 재설계는 하지 않았다.

bundled detector는1회 실행했다. 색138·글자79·radius21·font4로242개 advisory가 있었고 모두 Goal 시작 스냅샷에 있던 동일 소스 행이었다. 새 항목은0개다. 이후 포커스 ref·숫자 표시·활성 조건 요약은 소스·회귀 테스트·브라우저로 확인했다. WCAG 인증이나 전체 기존 advisory 해결을 의미하지 않는다.
