# 2026-09-13 검토 필요 경기 구현 점검

후속 요청으로 로스터 보완 기능을 구현하고 27경기에 적용했다.
[로스터 보완 구현과 적용 결과](2026-09-13-roster-supplement-application.md)를 참고한다.
아래 내용은 운영 반영 전 최초 점검 시점의 기록이다.

운영 catalog와 current manifest의 검토 필요 **76경기**를 점검했다. 시즌별로 2020년 18,
2021년 8, 2022년 20, 2023년 20, 2024년 5, 2025년 5경기다. 저장 차단 finding **7,598건**은
독립적인 오류 수가 아니라 collection·compiler finding과 후속 연쇄 차단의 합이다.

전 경기의 strict decode, 현재 문서 hash/content hash, source manifest와 gzip endpoint hash를 검증했다.
각 문서를 현재 compiler로 재계산하고 같은 저장 원문을 현재 mapper로 다시 처리했다.
실제 Naver 호출, 운영 문서 교정·재수집·승격·DB 적재, 서버 재시작은 수행하지 않았다.

책임 승계는 주자가 실제로 움직이는지와 무관하다. 기존 코드는 이동 목록의 책임만 갱신하여
베이스에 그대로 남은 주자의 책임이 빠졌다. 이동 검증 성공 뒤 최종 base occupant의 책임도 갱신하며,
가짜 진루 행을 만들지 않는다. 두 경기 모두 이전 투수 실점 1점을 구원투수에게 잘못 기록하던 문제다.
근거는 [KBO 2025 야구규칙 9.16(g), 인쇄 159–161쪽](https://6ptotvmi5753.edge.naverncp.com/KBO_FILE/ebook/pdf/2025_%EC%95%BC%EA%B5%AC%EA%B7%9C%EC%B9%99.pdf#page=182)이다.
병살·안타 후 추가 진루 중 주루사는 별도 예외이므로 합계를 맞추려고 책임을 일괄 바꾸지 않았다.

3루 생존 뒤 득점 사례는 원문의 두 이동 행이 모두 같은 출발지를 가진다. 첫 행은 베이스를 떠나지
않으므로 뒤의 홈인을 허용하되, 실제로 같은 출발지를 두 번 떠나는 이동은 계속 차단한다.
현재 저장본 재컴파일에서는 기존 잘못된 PA 문맥이 남은 tracking 2건이 차단된다. 원문 재처리로
정상 PA 연결을 재계산한 경우에만 0차단임을 확인했다. 운영에서 코드만 교체하면 자동 승격되는 것은 아니다.

콜드 종료 예외는 final 경기의 명시적 called_game 뒤 이닝·타자·교체 표시만 남은 경우에 한정했다.
뒤에 투구·타석 결과·주자 이동이나 미해결 종류가 있으면 적용하지 않는다. 모든 원문 행·identity·소스 위치를 유지한다.

## 가장 큰 미해결 개선 후보: 박스스코어 기반 로스터 보완

**27경기, 저장 차단 6,959건**은 preview의 bench/bullpen에서 빠진 선수로 인해 시작됐다.
같은 immutable bundle의 record 박스스코어에는 해당 선수 ID·이름·팀이 있었다.
record에서 확인된 선수만 메모리의 preview 후보 명단에 보완한 진단 실험은 **27경기 모두 0차단**이었다.
경기 중계나 점수·통계를 고친 결과가 아니다. 현재 mapNaverRoster는 preview만 사용한다.

이 실험은 제품 로스터 보완 기능으로 구현하지 않았다. 일반화할 때는 두 endpoint의 팀·이름·ID 충돌,
동명이인, 중복 row, 이름 없는 record, 투타 겸업, 선발 여부·타순을 보수적으로 처리하고 정확한
record 출처 finding을 남겨야 한다. 기존 ID를 다른 선수로 바꾸거나 이름만으로 로스터를 보충해서는 안 된다.
따라서 이 27경기는 수집 정규화 개선 대상으로 분류했다.

## 검증과 적용 상태

- Node 24.19.0, pnpm 10.15.1. 전체 테스트 651개, 격리 PostgreSQL 통합 테스트 38개 통과.
- format:check, typecheck, schema:game:check, build 통과. architecture 검증은 전체 테스트에 포함된다.
- 성능 fixture: 평균 1.278ms, p95 1.956ms로 10ms/25ms 기준 이내.
- 기본 lint는 기존 test-results 실험 코드 및 Python venv 내부 JavaScript 오류로 실패했다.
  test-results를 제외한 전체 제품·테스트 소스 ESLint는 통과했다. 관련 없는 실험 파일은 수정하지 않았다.
- 새 비식별 fixture 3개와 회귀 테스트 7개로 원문 보존, 결정론, atomic rollback, 실제 진행 뒤 종료 예외 거부,
  실제 중복 진루 차단을 확인했다.
- 대상 76경기의 current manifest와 document/content hash가 점검 전후 동일하다. source endpoint hash도 재확인했다.
- 운영 서버·DB에는 배포·적용하지 않았다. 5경기를 실제 검토 목록에서 제거하려면 작업본 보존 여부를
  확인하고 정상 correction/재정규화 경로로 검증·저장해야 한다. 봉인 revision은 변경하지 않았다.
- 통합 테스트 Docker 자원은 정상 정리됐다. 자동 승인 검토가 임시 소스 복사본 삭제를 정책상 차단하여
  복사본은 Git 제외 test-results/quarantine-review-20260913/integration-source에 남겼다.

진단 스크립트와 원문 주변 재현 자료는 Git 제외 test-results/quarantine-review-20260913에 있다.
audit.json, final/audit.json, roster-evidence.json이 최초 집계, 수정 후 비교, 로스터 보완 실험 결과다.
운영 데이터의 복사본은 진단 증거이며 새로운 파일 권위가 아니다.
