# 전체 UI 재설계 진행 기록

상태: 로컬 구현·검증 완료. 수집부터 분석까지 UI를 미니멀리즘·플랫 디자인으로 재설계하고,
실제 브라우저 점검과 독립 리뷰의 수정 사항을 반영했다. 작업 전 존재하던 미커밋 변경은 유지했다.

## 범위와 완료 증거

- 공통 셸·내비게이션·컨트롤·반응형: 키보드 탐색, 영역별 URL 복원, 좁은 화면 메뉴.
- 데이터 관리: 대시보드, 수집 현황/기록, 보정, 기록정정, DB 준비/저장/작업, 설정.
- 재생: 목록·경기·장면 이동, 스코어보드, 필드·트래킹, 근거 링크.
- 분석: 선수 탐색, 기본 기록, 구질, 코스, 선구안, 타자 성적, 최근 변화, 배합,
  운용, 매치업, 선수·팀 성적, 주루, 구장, 자료 품질, 모델 관리.
- 검증: 각 화면의 실제 렌더링, 대표 사용자 동작, 데스크톱·좁은 화면,
  관련 테스트 및 저장소 품질 게이트. 읽기 전용 운영 조회와 격리된 mutation 검증을 구분한다.

## 설계 근거

PRODUCT.md는 기존 요구와 저장소 문서의 제품 사실, DESIGN.md는 이번 요청의 디자인 기준이다.
frontend-design, Impeccable, kbo-analysis-ui를 사용했고 Graft에서 현재 소유 모듈을 확인했다.
Context7으로 React 접근성 ID 사용법, shadcn MCP로 그룹형 sidebar 예제를 확인했다.
현재 React·CSS 구조 안에서 필요한 패턴을 적용하며 새로운 컴포넌트 프레임워크로 전환하지 않는다.

## 초기 관측

- 관리 화면에 같은 크기의 카드가 반복되고 상태 수치와 다음 작업이 떨어져 있다.
- 분석과 관리의 글꼴·색상·컨트롤·여백이 서로 다르다.
- 수집 초기 상태에 미확인 수치와 빈 공간이 크게 노출된다.
- 분석은 설명·필터·표가 연속되어 핵심 공간 분포와 변화가 뒤로 밀린다.

## 구현 및 재점검 1

- 공통 토큰·글자 크기·여백을 통일하고 선수 이름, 선택 범위, 분석 탭의 위계를 정리했다.
- 대시보드는 상태 수치에서 실제 작업 목록으로 바로 연결한다. 수집 작업 수의 단위는 경기 대신 건이다.
- 수집·보정 초기 상태는 공통 `WorkflowGuide`의 세 단계 안내를 사용한다.
- DB 목록·상세 패널과 기록정정 큐를 평탄화하고 선택 상태를 접근성 속성으로 제공한다.
- 설정 진단은 행으로 표시하고 연결 구조는 펼침 영역에 둔다. API 응답 성공과 DB 장애를 구분한다.
- 코스 지도를 비교 표보다 먼저 배치하고 구질의 긴 표본 설명은 결과 뒤 펼침 영역으로 옮겼다.
- 자료 품질은 필드 보유율과 구장별 유효·누락·부적합 궤적 비율을 먼저 보여 준다. 정확한 수치는 유지한다.
- 투수 운용은 날짜 축의 투구 수 차트와 선택 등판 요약을 먼저 보여 준다. 기존 API 응답만 사용한다.
- 모델 관리의 현재 상태를 갱신 설정보다 먼저 배치했다. 최신 여부와 검증 채택을 구분한다.
- 재생의 사용자 안내에서 내부 구현 용어를 줄였다.
- 모바일 메뉴 이동 뒤 이전 스크롤이 남아 선수 이름이 상단바에 가려지는 문제를 실제 브라우저에서
  발견했다. 경로 변경 시 맨 위로 이동하고 같은 경로의 필터 변경에서는 위치를 유지하도록 수정했다.

### 실제 브라우저 확인 범위

개발 UI `127.0.0.1:5173`는 실행 시 프록시를 운영 API `127.0.0.1:8080`으로 지정했다.
운영 조회는 읽기 전용이며 수집 실행·교정 저장·모델 갱신을 누르지 않았다.

- 1440×1000: 대시보드, 선수 목록 검색과 손주영 선택, 코스, 구질, 최근 변화,
  투수 운용, DB 저장 경기 선택, 보정 초기 상태, 기록정정 초기 큐, 설정, 자료 품질, 모델 상태.
- 운용: 손주영의 30등판을 표시하고 2025-03-23을 선택했을 때 요약과 대면 기록이 함께 바뀜을 확인했다.
- 품질: 2025년 779경기·235,054투구·13구장과 기존 서버 수치의 표현을 확인했다.
- 390×844: 자료 품질, 선수 목록, 타자 검색, 김현수 반응·성적/기본 기록/선구안 탐색.
  메뉴 Escape 닫기 및 포커스 복귀, 페이지 가로 넘침 없음을 확인했다.
- 스크롤 수정 후 선구안: scrollTop 0, 상단바 하단 96px, 선수 영역 상단 112px로 이름이 가려지지 않았다.

  새 3단계 안내 구조를 확인하도록 수정한 후 고유 임시 Compose 프로젝트에서 통과했다.
  관리 6화면, 재생 장면/키보드, 분석 탐색·필터·차트·반응형, import/recovery/backup/restore,

## 구현 및 재점검 2

- 기본 기록에 팀별 AVG·OBP·SLG·OPS / ERA·IP·K%·BB% 요약을 추가했다. 이적 전후 비율과
  미확정 ERA를 합치지 않는다. 타입 검사에서 잘못 참조한 이닝 필드를 발견해 `outsRecorded`로
  수정하고 27아웃 → 9이닝 회귀를 추가했다.
- 선구안은 공간 지도·편차 차트를 코스 비교 표와 기간 비교보다 먼저 배치했다. 지표 카드의
  개별 테두리를 없애고 한 행의 요약으로 정리했다.
- 구장은 공통 0 기준 축의 관측 비율 비교와 분모를 먼저 보여 준다. 세 지표를 전환할 수 있고
  원시 평균의 한계, 시설 미확인, 상세 홈·원정 표와 근거 revision을 유지한다.
- 주루는 페이지 상단의 선수 선택 → 기회 결과 → 경기 장면으로 구성했다. 목록 선택 시
  조회가 끝난 뒤 요약 제목으로 포커스와 스크롤을 옮긴다. 미상 기회의 null 비율을 유지한다.
- 매치업은 직접 상대와 유사 조건의 표본 수·스윙·헛스윙·루킹을 공통 0–100% 축으로 비교한다.
  분모·분자·소표본 안내를 유지하고 상세 기록·정의·직접 타석은 펼침 영역으로 옮겼다.
  모델 기대 반응은 관측 비교 뒤에서 요청할 때 조회한다.
- 모든 요약은 기존 응답의 표시 모듈로 분리했다. 서버·DB·야구 계산 권위는 바꾸지 않았다.

- 독립 finish review의 첫 판정은 `recapture`였다. 기본 기록 데스크톱과 주루 모바일의
  이전 캡처가 올바른 크기·스크롤 상태를 담지 못했다. 현재 viewport와 scrollY를 확인하고
  같은 경로에 재촬영해 전체 재검토를 요청했다. 이 첫 판정을 디자인 승인으로 취급하지 않는다.

## 독립 마무리 검토

첫 유효한 독립 리뷰의 판정은 `fix`였다. 재생 점수판의 그라데이션·장식 원,
이닝·속도 문구의 줄바꿈, Unicode 재생 아이콘, 기본 기록 모바일 캡처의 경계,
설계 방향 문서의 누락을 지적했다.

- 점수판을 `--ui-ink` 단색으로 바꾸고 장식 원을 제거했다.
- 이닝의 글자 줄바꿈을 막고 좁은 화면의 중앙 폭을 확보했다. 속도 선택기의 폭·축소도 고정했다.
- 재생 아이콘은 16px SVG 모듈로 분리했으며 버튼의 접근 가능한 이름을 유지했다.
- 기본 기록 모바일의 실제 너비는 390px, 문서 폭 375px, 선수 변경 오른쪽 363px,
  요약 오른쪽 338px였다. 렌더링 잘림이 아닌 이전 캡처 오류였고 같은 경로에 재촬영했다.
- DESIGN.md와 `.impeccable/design.json`은 실제 토큰·컴포넌트·반응형과 고정 방향을 기록한다.
  다섯 방향 블록은 사후 문서임을 명시했다. 실행하지 않은 seed·comp·사전 승인 절차를
  실행했다고 기록하지 않았다.

동일 reviewer가 수정 5건을 모두 `resolved`, 회귀 없음, `remaining: clear`,
`disposition: ship`으로 판정했다. 이는 해당 수정 목록에 대한 판정이며 전체 상태의 무결점
보증으로 확대하지 않는다. 최초 리뷰는 관리·보정·재생과 주요 분석 대표 캡처를 검토했고,
빠진 선수 탐색·코스·최근 변화·운용·타자 반응은 별도 추가 범위로 검토한다.

마지막 재생 표시 수정 뒤 기존 재생·접근성 15테스트와 lint·typecheck·build가 통과했다.
문서화 뒤 전체 format:check와 JSON 파싱·참조 검증, `git diff --check`도 통과했다.
전체 1,229테스트와 격리 E2E는 위 라운드에서 통과했으며 표시만 바뀐 마지막 수정 때문에
DB·학습·backup/restore 전체 절차를 반복하지 않았다. Graft의 최종 범위는 727파일이다.

격리 프로젝트 `kbo-stage6-63312-f4bfc510`의 소유 라벨을 확인한 컨테이너 4개, 볼륨 1개,
네트워크 2개와 정확한 임시 workspace/backup 폴더를 정리했다. 운영 DB·workspace는
수정하지 않았다. 운영 배포·커밋·푸시도 수행하지 않았다.

## 최종 판정과 검증 범위

추가 독립 리뷰는 선수 탐색·투수 코스·최근 변화·등판 운용·타자 반응의 유효 캡처 11개에서
`disposition: ship`, `material_fixes: 없음`으로 끝났다. 최초 리뷰의 수정 목록도 모두 해결됐다.
부모 에이전트의 전체 화면·대표 동작 검증과 관련 회귀·E2E 결과를 합쳐 이번 로컬 UI 작업을 완료한다.

독립 시각 리뷰는 전달한 viewport와 상태만 검토했다. 미촬영 영역이나 가능한 모든 조건을
무결점으로 보증하지 않는다. 로딩·오류·키보드·저장 수명은 관련 테스트와 격리 E2E로 보완했다.
브라우저 캡처는 `test-results/ui-redesign/`에 있으며, 파일명에 `before`가 있는 것은 이전 상태다.
운영 배포·커밋·푸시는 이 재설계 목표에 포함하지 않는다.
