# 중복 투구 교정 사례

## 원장에 남길 행을 고른 근거

한 경기에서 같은 공을 나타내는 중계 행 두 개 중 첫 행은 실제 투구, 두 번째 행은 중계 안내로 남아 있었다. 세 쌍 모두 타자·투수 문맥, 투구 순번·판정·관찰 상태와 PTS 측정값이 같았다. 원본의 앞뒤 순서를 따라 비교하니 첫 행의 구속은 직전 공의 PTS 속력 반올림값에, 두 번째 행의 구속은 대상 공의 PTS 속력 반올림값에 각각 일치했다.

| 대상 공        | 기존 봉인값       | 직전 공 PTS 속력 (km/h) | 대상 공 PTS 속력 (km/h) | 복원한 두 번째 행 |
| -------------- | ----------------- | ----------------------: | ----------------------: | ----------------- |
| 3회초 3구 볼   | 128 km/h·슬라이더 |                  128.26 |                  131.33 | 131 km/h·슬라이더 |
| 3회말 2구 파울 | 145 km/h·직구     |                  144.80 |                  133.55 | 134 km/h·포크     |
| 9회초 5구 파울 | 139 km/h·직구     |                  138.95 |                  138.26 | 138 km/h·직구     |

보관한 KBO 문자 중계는 각 순번과 판정을 한 번씩 보여 주었다. 이 세 중계에 구속·구종 표시는 없었다. 같은 경기의 비교 대상 257구 가운데 219구에서 중계 구속과 PTS 50ft 속력 반올림값이 일치했다. 속력 대조는 각 원문과 앞뒤 관계를 함께 판단하는 보조 근거로 사용했다. 3회말 투구는 속력과 수직 가속도가 같은 투수의 포크 13구 범위에 들었고 직구 38구 범위를 벗어났다. 후행 행을 채택한 판단은 이 세 쌍에 적용했다.

## 반영에서 확인한 것

- 두 번째 행의 원래 `pitch`를 복원하고 기존 실투구 세 행을 삭제했다. 각 복원 행에 원천 위치와 PTS를 대조한 관측을 하나씩 재연결했다. 삭제된 행의 관측도 원장 tracking 후보에서 보존됐다.
- 격리 사본과 운영에서 517→514행, 3–2, 실제 투구 280개, 완료 타석 77개, 차단 0건, 경고 8건을 확인했다. 구속·구종 기반 분석의 입력으로 쓰이는 봉인값이 바뀌었다.
- revision 3의 해시를 보존하고 revision 4를 봉인했다. 새 revision의 489개 replay frame을 읽고 frame hash를 다시 계산했다. 삭제한 이벤트 ID 세 개는 사라졌고, 복원한 ID 세 개에는 표의 값과 예상한 tracking link가 하나씩 있었다.

같은 투구 ID의 문맥이 다르면 별개 표본으로 유지한다. 최초 투구 payload에 값이 빠졌거나 메타데이터만 다를 때도 판정·상태와 원본 PTS를 비교해 남길 identity를 결정한다.
